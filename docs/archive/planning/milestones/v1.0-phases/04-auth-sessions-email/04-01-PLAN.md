<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| API → `oxidean-db` → SQL engines | Auth PII + password hashes + session token hashes persist |
| Migration SQL → live schema | Schema defines uniqueness and nullable password for SSO users |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Information disclosure | `users.password_hash`, `sessions.token_hash` | mitigate | Store Argon2id PHC and SHA-256(session) only (hashing in later plans); columns are hash-only TEXT; never store raw cookie token (RESEARCH pitfall 4) |
| T-04-02 | Tampering | username/email uniqueness | mitigate | UNIQUE constraints on `email` and `username` in all three dialects; app normalizes email to lowercase before insert |
| T-04-03 | Elevation of privilege | `users.is_admin` | mitigate | Column defaults FALSE; only admin-seed path (04-04) or later Phase 6 sets true — no public insert API in this plan |
</threat_model>

- `avatar_path` TEXT NULL
