<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Fork PR → CI runner | Untrusted code executing with runner-local database services |
| CI service containers → job steps | Default credentials on localhost-bound Postgres/MySQL |
| Public docs → operators | Documented defaults become production defaults if written carelessly |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-16 | Elevation | CI secrets exposure to fork PRs | mitigate | `db-matrix` uses no `secrets.*`; all credentials are the literal throwaway value `oxidean` on runner-local services (continues T-01-12) |
| T-02-17 | Information disclosure | CI logs leaking connection strings | accept | Matrix `database_url` values are non-secret localhost throwaways; the application itself redacts passwords in its own error output (T-02-01) |
| T-02-18 | Information disclosure | docs encouraging weak production credentials | mitigate | `docs/database.md` and `.env.example` label `oxidean`/`oxidean` as local-only and instruct operators to set real credentials plus a non-public bind before exposing an instance |
| T-02-19 | Tampering | undocumented destructive dialect switch | mitigate | `docs/database.md` states the switch applies to an empty target only, copies no data, and that cross-dialect data migration is out of scope for this phase |
</threat_model>

1. Append a `db-matrix` job to `.github/workflows/ci.yml`, following the existing job style (`actions/checkout@v4`, `dtolnay/rust-toolchain@stable`, `Swatinem/rust-cache@v2`):

```yaml
  db-matrix:
    name: db-${{ matrix.dialect }}
    runs-on: ubuntu-latest
    strategy:
      fail-fast: false
      matrix:
        include:
          - dialect: postgres
            database_url: postgres://oxidean:oxidean@localhost:5432/oxidean
          - dialect: mysql
            database_url: mysql://oxidean:oxidean@127.0.0.1:3306/oxidean
          - dialect: sqlite
            database_url: sqlite:./var/oxidean.db
    services:
      postgres:
        image: postgres:16-alpine
        env:
          POSTGRES_USER: oxidean
          POSTGRES_PASSWORD: oxidean
          POSTGRES_DB: oxidean
        ports: ["5432:5432"]
        options: >-
          --health-cmd="pg_isready -U oxidean" --health-interval=5s --health-timeout=5s --health-retries=10
      mysql:
        image: mysql:8.4
        env:
          MYSQL_USER: oxidean
          MYSQL_PASSWORD: oxidean
          MYSQL_DATABASE: oxidean
          MYSQL_ROOT_PASSWORD: oxidean
        ports: ["3306:3306"]
        options: >-
          --health-cmd="mysqladmin ping -h 127.0.0.1 -uroot -poxidean" --health-interval=5s --health-timeout=5s --health-retries=20
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
      - uses: Swatinem/rust-cache@v2
      - name: migrate + probe (${{ matrix.dialect }})
        env:
          DATABASE_URL: ${{ matrix.database_url }}
          OXIDEAN_DB_DIALECT: ${{ matrix.dialect }}
        run: cargo test -p oxidean-db --test dialect_probe -- --nocapture
```

   Both service containers boot on every leg because GitHub Actions cannot condition `services:` on `matrix.*` (RESEARCH pitfall 7); that is an accepted few-seconds cost on the sqlite leg. Add a comment above the job saying so, so the next reader does not "fix" it.
2. Set `OXIDEAN_DB_DIALECT` on every leg deliberately: it exercises the D-01/D-02 agreement path in CI, not just the URL inference.
3. Extend the existing `compose` job with a third step validating the new overlay (do **not** add bring-up):

```yaml
      - name: docker compose sqlite overlay config
        run: docker compose -f docker-compose.yml -f docker-compose.sqlite.yml config
```

4. Leave the `rust`, `js`, `rpc-sync`, and existing `compose` steps unchanged; `cargo test --workspace` in the `rust` job continues to run with no `DATABASE_URL`, exercising the graceful-skip path.
