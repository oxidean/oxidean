## Visual hierarchy & layout contracts

### Shared auth shell (`/setup`, forced-change)

**Inherit Phase 4/5 auth shell exactly:**

| Rule | Contract |
|------|----------|
| Chrome | Global `SiteHeader` + `SiteFooter` — while `needs_setup`, header **omits** Sign in / Sign up account CTAs (instance not ready); mark + theme OK |
| Page column | Centered; **max-w-md** (`28rem`); page padding **3xl** vertical / **md** horizontal |
| Brand | `OxideanMark` **48×48** above title — no duplicate wordmark in panel |
| Title | Heading (24 / 600 / 1.2 Sora) |
| Support | One Body muted sentence under title |
| Surface | Flat on `--background`; optional single `bg-card` panel only if needed for contrast |
| Atmosphere | Soft cool↔warm radial mesh allowed (same as login/signup) |
| Loading | `AuthFormSkeleton` until status ready; submit shows disabled + **Working…** |
| Errors | `AuthErrorBanner` above fields — problem + next step |

Reuse `AuthShell` + `AuthErrorBanner`; do not fork a second shell.

### `/setup` (AUTH-07 wizard)

| Element | Contract |
|---------|----------|
| Route | `/setup` — only while `needs_setup`; if not needed → SSR/client redirect `/` |
| Title | **Set up this instance** |
| Support | Create the system admin account. This is a one-time step for an empty database. |
| Fields | Email; Username (+ Phase 4 helper); Password; Confirm password — same Input contracts as signup |
| Reserved usernames | Wizard may use reserved names (e.g. `admin`) per backend; do not show a scary reserved error for allowed bootstrap names |
| `allow_signup` | **Switch** + Label **Allow open signup** (default **off**). Helper Label under: “When off, new accounts can’t self-register. You can change this later in Auth settings.” |
| Primary CTA | **Create system admin** (full-width on narrow, ≥44px) |
| Success | Issue session → redirect **`/`** (SSR SignedInHome) — no toast required |
| Unavailable | If `auth.setup_unavailable`: banner copy → then redirect `/` or Sign in |
| Document title | `Set up Oxidean` → prefer pattern **`Set up · Oxidean`** (Phase 3 `Page · Oxidean`) |

**Field order:** Email → Username → Password → Confirm → Switch → CTA.

### Forced credential change (ENV-seeded only — D-16/D-17)

| Element | Contract |
|---------|----------|
| Route | **`/setup/credentials`** (or `/force-credentials` if router prefers flat — **lock: `/setup/credentials`**) |
| Who | Only ENV-seeded `sys-admin` with `must_change_credentials` (or equivalent) flag; wizard-created admins **skip** |
| Gate | SSR/server: if flag set, all app UI (except this route + status/health) redirects here until cleared |
| Title | **Confirm admin account** |
| Support | Review your admin email and username. Change any still-default values before continuing. |
| Email | Prefill ENV email — **may keep** if operator-provided (not a placeholder). Editable. |
| Username | Prefill `system-administrator` — this is a **default**; **must change** to a non-default before submit |
| Password | Empty fields — **Keep current password** Switch default **on** when ENV password was set; turning off reveals New password + Confirm (min 8). If Keep on, do not require new password |
| Defaults that must change | Username still equal to `system-administrator` (case-insensitive). Do **not** force email/password change when they are operator ENV values |
| Primary CTA | **Save and continue** |
| Success | Clear flag → honor safe `returnTo` else `/` |
| Document title | `Confirm admin · Oxidean` |

### `/` SSR home (folded flicker fix — D-18…D-22)

| Rule | Contract |
|------|----------|
| Priority | **`needs_setup` → `/setup`**; else valid session → **SignedInHome**; else **marketing landing** |
| First paint | HTML matches final tree — no marketing flash for signed-in; no SignedInHome flash for anonymous |
| `/dashboard` | Direct navigation → **404** (remove public file route / soft redirect) |
| Presence hint | Keep `oxidean_signed_in` as progressive enhancement; drop if it fights SSR |
| Post-login / post-forced-change | Safe `returnTo` else `/` |

### Closed signup (`allow_signup === false`)

| Rule | Contract |
|------|----------|
| `/signup` | **HTTP/SPA 404** — not an AuthShell explanation page |
| Logged-out UI | **No references** to `/signup`: hide header **Sign up**; hide landing **Get started** / signup CTAs that target `/signup`; remove login cross-link “Create an account” / Sign up |
| Logged-in UI | Unchanged (no signup CTA) |
| When `allow_signup === true` | Restore Phase 4 Sign up / Get started / login cross-link behavior |
| Public config | Expose `allow_signup` (or equivalent) on a public bootstrap/provider config so chrome can hide links without authed admin RPC |

### `/admin/auth` extension

| Element | Contract |
|---------|----------|
| Control | Same **Switch** + Label **Allow open signup** + same helper |
| Placement | Near top of auth settings after provider mode (executor: with instance access settings) |
| Persistence | Matches ENV/wizard setting |

1. **Create system admin**, **Save and continue**
