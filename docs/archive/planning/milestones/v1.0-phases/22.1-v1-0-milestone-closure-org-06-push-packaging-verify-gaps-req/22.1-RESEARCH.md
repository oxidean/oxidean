## Summary

Phase 22.1 is a **packaging + honesty** closure, not a new product surface. ORG-06 merge enforcement already works via `evaluate_merge`; the audit blocker is that **direct push** in the shipped Compose/API path is fail-open because (1) `oxidean-protection-hook` is never built/copied into the API image, (2) Compose never sets `OXIDEAN_PROTECTION_HELPER`, (3) Smart HTTP only reads the env and does not call `default_helper_path()`, (4) SSH `receive-pack` does not inject helper/DB/repos/capability env into the git child, and (5) the installed `hooks/update` script exits 0 when the helper is missing. Forks via `clone_bare` never call `install_protection_hooks` (unlike `init_bare`), so even a packaged helper leaves forks unprotected until reconcile.

In parallel, eleven executed phases lack `*-VERIFICATION.md`, PLAT-* checkboxes lag evidence, WINDOWS `open_count` is 55 (mostly obsolete Wave 0 stubs), and Nyquist honesty for phases 8/14/15/20 needs `/gsd-validate-phase`. Sequence locked by D-VER-04: **ship ORG-06 packaging first**, then thorough verify 13 + 22; lightweight VERIFICATIONs and WINDOWS/REQUIREMENTS hygiene can interleave.

**Primary recommendation:** Extend the existing API Dockerfile to build/copy `oxidean-protection-hook` beside `oxidean-api`, wire Compose + Smart HTTP fallback + SSH env (including capability), change the update-hook script for production fail-closed, install hooks in `clone_bare`, add boot sweep + Compose protected-push smoke, then run the hybrid VERIFICATION / validate-phase / WINDOWS waive / PLAT flip program.

### Pattern 1: Sibling helper path + Compose explicit env
**What:** Build helper next to API; set Compose env to absolute path; Smart HTTP falls back to `default_helper_path()` when env unset.
**When to use:** Always for ship path (D-PKG-01).
**Example:**

```rust
// Source: crates/oxidean-api/src/protection/mod.rs:410-419 (existing)
pub fn default_helper_path() -> Option<PathBuf> {
    std::env::current_exe().ok().and_then(|p| {
        let sibling = p.parent()?.join("oxidean-protection-hook");
        if sibling.is_file() {
            Some(sibling)
        } else {
            None
        }
    })
}

// Planned Smart HTTP resolution (planner/executor):
let helper = std::env::var("OXIDEAN_PROTECTION_HELPER")
    .ok()
    .filter(|s| !s.is_empty())
    .or_else(|| default_helper_path().map(|p| p.display().to_string()));
```

### Pattern 2: Install hooks on every bare creation path
**What:** `init_bare` already installs; `clone_bare` must call the same installer; boot sweep catches pre-existing bares.
**When to use:** All bare repo births + API boot (D-FORK-02, D-PKG-04).
**Example:**

```rust
// Source: crates/oxidean-git/src/cli.rs:396-397 (init_bare today)

// Planned end of clone_bare after successful `git clone --bare`:
```

### Pattern 3: Production fail-closed update hook
**What:** Change the embedded `hooks/update` script so missing/non-executable helper denies updates when `OXIDEAN_ENV` is production-like; keep fail-open for `development`/`dev`/`compose` (discretion: treat `compose` as fail-open so local without helper still works; Compose smoke proves helper is present).
**When to use:** `install_protection_hooks` overwrite (boot + create/clone).
**Recommended production-like set:** `production` and `cloud` (matches webhook URL hardening in `webhook/deliver.rs`). `[ASSUMED]` for whether `compose` should also fail-closed in CI — recommend **no** (rely on smoke asserting binary + denial).

## Common Pitfalls

### Pitfall 1: Smart HTTP `env_clear` drops helper
**What goes wrong:** Compose sets helper on API process, but CGI child never sees it.
**Why it happens:** `run_git_http_backend` clears env then selectively re-adds `[VERIFIED: crates/oxidean-api/src/git/http_backend.rs:64-90]`.
**How to avoid:** Always pass `helper_path` in `ProtectionCgiEnv` (env var or `default_helper_path()`).
**Warning signs:** HTTPS push succeeds on protected branch while unit tests pass.

### Pitfall 2: SSH Admin treated as Read
**What goes wrong:** `OXIDEAN_ACTOR_CAPABILITY` unset → helper uses `read` → Admin cannot bypass when `enforce_admins=false`.
**Why it happens:** `AuthzDecision::Allow` omits capability; `run_pack_command` sets no env `[VERIFIED: crates/oxidean-api/src/ssh/pack.rs:28-35,196-204]`.
**How to avoid:** Extend Allow with capability (or parallel arg); set `OXIDEAN_ACTOR_CAPABILITY`, `OXIDEAN_PROTECTION_HELPER`, `OXIDEAN_DATABASE_URL`, `OXIDEAN_REPOS_DIR` on receive-pack only.
**Warning signs:** Admin SSH push to protected branch denied unexpectedly; Write user push allowed when helper missing.

### Pitfall 3: Fail-open script survives packaging
**What goes wrong:** Image has helper but old repos keep old hook script that exits 0 when helper unset.
**Why it happens:** `reconcile_protection_hooks` skips if `hooks/update` exists `[VERIFIED: crates/oxidean-git/src/cli.rs:52-58]`.
**How to avoid:** Boot sweep should **overwrite** via `install_protection_hooks` (not reconcile-only) so script upgrades apply; new installs already overwrite.
**Warning signs:** Pre-phase repos still fail-open after upgrade.

### Pitfall 4: `clone_bare` without hooks
**What goes wrong:** Forked repos accept direct pushes on protected patterns until touched by reconcile.
**Why it happens:** `clone_bare` ends after `git clone --bare` with no hook install `[VERIFIED: crates/oxidean-git/src/cli.rs:1045-1064]`.
**How to avoid:** Install hooks inside `clone_bare`; on failure, compensate fork like clone failure (D-FORK-04). Prefer reuse `repo.fork_failed` unless a more specific code is needed (discretion).
**Warning signs:** Audit WARNING SOC-04 / ORG-06 fork path remains.

### Pitfall 5: Compose smoke without Docker / without protected rule setup
**What goes wrong:** Smoke only checks `/health` and never proves denial.
**Why it happens:** Current `compose-smoke.sh` is dialect/Traefik health oriented.
**How to avoid:** After bring-up: assert helper executable in container; create repo + protection rule requiring reviews; attempt HTTPS push; expect non-zero. Include SSH when TCP published (Compose already maps `2222:2222`).
**Warning signs:** Re-audit still flags packaging blocker.

### Pitfall 6: Flipping PLAT before VERIFICATION
**What goes wrong:** REQUIREMENTS claim Complete without evidence artifact.
**Why it happens:** Integration is wired but checkbox lag was intentional process debt.
**How to avoid:** Strict D-HYG-02 order: VERIFICATION `passed` → then flip PLAT-01/04–08/10–11. Leave PLAT-02/03/09 Complete.

### Pitfall 7: Mass-waive without spot-check
**What goes wrong:** Real remaining debt waived.
**How to avoid:** D-HYG-01/03 — waive only Wave 0 stubs whose owning plan shipped; spot-check sample files; keep current deviations (e.g. coverage floor 11.1 if still true).
