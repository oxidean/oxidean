## Summary

Reviewed Rust/shell/Makefile/Dockerfile sources from plans 01–04 (ORG-06 packaging, fail-closed hooks, SSH receive-pack env, boot hook sweep). Plans 05–10 were VERIFICATION/VALIDATION/planning-only and were excluded. Packaging, helper resolution, SSH protection env injection, clone_bare hook install, and Compose smoke look largely sound; the main defect is boot ordering that opens a protection bypass window on SSH before the sweep finishes.

## Critical Issues

### CR-01: SSH accepts pushes before protection hook sweep

**File:** `crates/oxidean-api/src/main.rs:82-106`
**Issue:** `maybe_spawn_from_env` starts the SSH listener before `sweep_protection_hooks`. On upgrade hosts where existing bares lack `hooks/update` (or still have stale fail-open scripts), SSH `receive-pack` can accept ref updates with no (or outdated) protection hooks for the entire duration of the serial repos-dir walk. HTTP is also bound and logged as listening before the sweep, though `axum::serve` has not started yet. D-PKG-04’s purpose is exactly to close that gap; starting SSH first reopens it at every boot.
**Fix:** Run the sweep (and preferably only then spawn SSH / serve HTTP):

```rust
let state = oxidean_api::AppState::new(db, email, env_name);
let sweep = oxidean_api::protection::sweep_protection_hooks(&state.repos_dir).await;
// log sweep errors as today…
let _ssh_stop =
    oxidean_api::ssh::maybe_spawn_from_env(state.db.clone(), state.repos_dir.clone()).await;
let listener = tokio::net::TcpListener::bind(&bind).await…;
tracing::info!("oxidean-api listening on {bind}");
// jobs + axum::serve…
```

If SSH must start early for other reasons, gate `receive-pack` until sweep completes (oneshot/flag) — do not leave unprotected bares reachable.

## Warnings

### WR-01: `make smoke-protection` not in CI fail-closed protocol gate

**File:** `Makefile:166-193`
**Issue:** ORG-06 packaging smoke is a sibling target and is not invoked by `smoke-protocol-ci` / `.github/workflows/ci.yml` `smoke-protocol`. Helper packaging regressions (Dockerfile COPY drop, Compose env drift, HTTPS denial breakage) will not fail PR CI unless someone runs `make smoke-protection` manually. SUMMARY notes this as intentional, but it leaves the packaging tracer ungated.
**Fix:** Add `./scripts/compose-smoke-protection.sh` to `scripts/ci-smoke-protocol.sh` (or a dedicated CI job with `SMOKE_REQUIRE_STACK=1`), or document an explicit scheduled/manual gate and link it from the CI matrix.

### WR-02: Compose protection smoke always builds an `http://` git remote

**File:** `scripts/compose-smoke-protection.sh:139-141`
**Issue:** `AUTH_URL` strips `http://`/`https://` from `BASE_URL` then hardcodes `http://git:…@…`. Against an HTTPS-only Traefik/origin (`OXIDEAN_SMOKE_URL=https://…`), clone/push can fail for the wrong reason or bypass TLS expectations while still claiming packaging success.
**Fix:** Preserve the original scheme:

```bash
SCHEME=http
[[ "$BASE_URL" == https://* ]] && SCHEME=https
AUTH_HOST="${BASE_URL#http://}"
AUTH_HOST="${AUTH_HOST#https://}"
AUTH_URL="${SCHEME}://git:${PAT}@${AUTH_HOST}/${OWNER}/${REPO}.git"
```

### WR-03: Boot continues after sweep errors; some bares may stay unprotected

**File:** `crates/oxidean-api/src/main.rs:106-114` and `crates/oxidean-api/src/protection/mod.rs:561-572`
**Issue:** Per-repo `install_hooks` failures increment `errors` and the API still listens. Combined with fail-open behavior when `OXIDEAN_ENV` is not `production|cloud` and the helper is missing, a subset of repos can remain without enforceable protection after boot. Logging is present; there is no operator-facing fail metric/alert or optional fail-closed boot flag.
**Fix:** At minimum emit a structured error counter/metric and document the ops runbook. Prefer an opt-in `OXIDEAN_PROTECTION_SWEEP_FAIL_CLOSED=1` (or production default) that exits non-zero when `errors > 0` after sweep.

## Info

### IN-01: Misleading “listening” log before `axum::serve`

**File:** `crates/oxidean-api/src/main.rs:91-126`
**Issue:** Log says listening immediately after `TcpListener::bind`, but the accept loop starts only after the (potentially long) sweep. Healthchecks may connect and hang until serve starts.
**Fix:** Move the info log to just before/after `axum::serve`, or log “bound; sweeping hooks…” then “serving”.

### IN-02: `map_rule` swallows first `try_get::<i32>` error

**File:** `crates/oxidean-db/src/branch_protection.rs:56-70`
**Issue:** Any `i32` decode failure falls through to `i64`. Correct for Postgres INT4 vs SQLite, but a real column/type mismatch could be masked until the `i64` path also fails.
**Fix:** Match on the error kind / dialect, or try `i64` only when the error indicates a type mismatch.
