<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Issue/resend RPC → EmailSender | Flooding / OTP brute-force adjacent |
| Magic-link URL construction | Host-header injection if origin untrusted |
| Signup path → verify mail | Must not block account creation on mail failure |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-05 | Denial of service | verify issue/resend | high | mitigate | Soft limits ≥60s between issues per (user_id, purpose) and ≤5 per rolling hour; return `auth.rate_limited`; replace-on-resend (D-19) |
| T-05-06 | Elevation of privilege | OTP attempts | high | mitigate | Cap ~10 failed redeem attempts per issuance then invalidate; single-use consume; 30m TTL (D-18, D-20) |
| T-05-07 | Spoofing | magic-link absolute URL | high | mitigate | Build links only from `OXIDEAN_PUBLIC_ORIGIN` (strip trailing slash); never from request Host alone |
| T-05-08 | Information disclosure | email/log sink | high | mitigate | Never log plaintext OTP/token; welcome+verify may both send; mail send failure on verify must not fail signup (mirror welcome) |
</threat_model>
