### Review — connector-gateway functional-design, iteration 2

**Reviewer:** aidlc-architecture-reviewer-agent
**Iteration:** 2
**Verdict:** NOT-READY

### Review
Re-verified all 26 iteration-1 findings adversarially against the current `entities.md`, `rules.md`, `functional-spec.md`, `traceability.json`, the amended `contract-summary.md`, and `stories.md` (AC1.5.2). The fixes are largely real, not cosmetic: both C1 amendments (`lifecycle` + `pairing_id` on Target, `pairing_id` in the `pairing_create` return, `target_get`, `grant_respond.scope`) and the C7 amendment (user_id-leading signatures, pinned `Denied{reason, grant_id?}`, additive `result_summary`) are committed in-place in the contract file and correctly flagged per the deviation rule — additive-only, consumer-proposed, so contract-ownership convention is honoured. BR4.1(4) now admits only allowed+unexpired `action_session` grants, pending grants join solely on identical stored args, and `action_once` consumption is pinned via `resolved_at` plus the kind check — no unconsented-queue or consent-replay path remains. The BR2.2/BR5.2/BR6.3 report-terminal-close exception and BR6.1's direct-`cancelled` disconnect are consistent across all three rules and the entity constraints. However, two Majors stand: (a) the R-06 fix is incomplete — `entities.md` §Target constraints still contains the exact rotation text the finding flagged, contradicting BR6.1/WF4's new-row-per-pair; (b) the R-08 fix introduced a new contradiction — `ON DELETE CASCADE` makes BR6.5/WF5's claimed cancel delivery via claim/heartbeat impossible, since the `cancel_requested` rows are deleted before any connector touch can observe them. Eight Minor stale-text/edge nits also remain.
