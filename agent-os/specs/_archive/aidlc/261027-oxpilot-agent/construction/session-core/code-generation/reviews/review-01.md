## Review

Adversarial review of the `session-core` (U2) Code Generation output against the approved plan, the C1/C2/C5-amended/C8 contracts, and the functional + NFR designs. All 21 `source-manifest.json` writes were read against the actual working tree, plus the directly implicated files the manifest omits.

Verified as correct and therefore not findings: the `SessionService` trait is exactly 21 verbs, `user_id` first on every method, `Result<_, AppError>` throughout, `oxidean-db` row structs on reads (`oxidean-api-core/src/oxpilot.rs:301-422`); `enqueue` dedupes transcript-then-queue with `{null, null}` on transcript hits and an ordinal `COUNT(queue_seq < mine)+1` position (`services.rs:367-443`); `drain_queue_tx` is atomic per dialect with queue_seq ordering and seq minted inside the tx, and `upsert_usage` writes user + `__instance__` in one transaction (`oxidean-db/src/oxpilot.rs`); `check_budget` checks user before instance with `data:{scope}` and `usage_view` never refuses; `budget_caps` is stamped on every `OxpilotRuntimeSlot` constructor path including `carried_slot(&EffectiveProviderConfig)` and `disabled_slot(caps)`; `install_sessions` runs unconditionally at `crates/oxidean-api/src/main.rs:120` and `sessions()` answers `oxpilot.internal` when unset; all five procs are `SessionOnly` (fail-closed classify + closed-set test), run `require_enabled`, and `session_delete` audits all three outcomes; `snapshot_frame` merges tool calls by `message_id` ordered by `call_index` and the queue in `queue_seq` order; migration 0087 is correct on all three dialects with cascades on the three child tables, both uniques on the queue table, and a standalone usage-counters table; `rpc_gen.rs` and the regenerated `packages/api-client/src/index.ts` cover all five procedures (fresh regeneration is deterministic — the `rpc-sync-check` nonzero exit is only the uncommitted generated diff vs the index, not generator drift); no `oxidean-api-core → oxidean-api-oxpilot` edge, no `#[ignore]`, no secrets.

Executed locally: `cargo check -p oxidean-api-oxpilot -p oxidean-api-core --tests` (clean), `cargo nextest run -p oxidean-api-oxpilot` (78 passed), `cargo nextest run -p oxidean-api-core -E 'test(oxpilot)'` (7 passed), `cargo nextest run -p oxidean-db -E 'binary_id(oxidean-db::dialect_oxpilot)'` (16 passed, sqlite leg), `cargo nextest run -p oxidean-api -E 'binary_id(oxidean-api::oxpilot)'` (18 passed). The working tree also carries substantial unrelated modifications (U1/U4 oxpilot surfaces, web files, AIDLC records); review scope was the unit's diff.

The blocking defects: `chat_post` never consults the queued half of the union dedupe, so a resent `client_msg_id` that exists only in `oxpilot_queued_messages` inserts a transcript duplicate that permanently poisons `drain_queue_tx` (R-01); `message_queue` runs budget and liveness before ownership, inverting BR4.1's pinned order and leaking session existence for foreign ids (R-02); `delete_session` rewrites hook errors instead of merging `hook_index` into them (R-03); and `last_activity_at` is touched on only two of the nine child-write paths the entity contract enumerates (R-04).
