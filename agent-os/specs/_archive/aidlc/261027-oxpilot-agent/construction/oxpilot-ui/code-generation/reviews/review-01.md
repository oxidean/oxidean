### Architecture Review — code-generation (oxpilot-ui)

### Review

**Reviewer:** aidlc-architecture-reviewer-agent
**Verdict:** NOT-READY
**Iteration:** 1

Adversarial pass over every file the unit ships: all 14 `components/oxpilot/*`, both routes and astro entrypoints, `oxpilot-{chat,stream,queries}` + `route-params`, the tanstack-ai-octane vite plugin, both coverage manifests, all four test files, and the three server amendments end-to-end (0090 ×3 dialects → `oxpilot.rs` store legs → `services.rs`/`gateway.rs` → `session.rs`/`procs.rs` → `dispatch.rs`/`lib.rs` → `rpc_gen.rs` ↔ `packages/api-client`). The production code is largely faithful — the C2 stream contract is implemented end-to-end (first-snapshot skip, `(message_id,seq)` dedupe, keyed reseed, foreign-turn detection, single-probe fatal), the security surface is clean (one-shot pairing code confined, one allowlisted innerHTML seam on an escaped pipeline, zero storage/eval/console hits, every destructive ride confirmed), and the server amendments are registered, owner-scoped, and lazy-expiry-preserving. What blocks acceptance is the evidence layer plus several pinned behaviors: the browser-coverage manifest fails its own checker deterministically and claims subjects that do not exist; the three mandated web test extensions and the three proc-level server tests did not land despite `unit-test-instructions.md` and `code-summary.md` implying otherwise; `budget_exceeded` never renders the named-env notice; a failed send destroys the composer draft; and both routes nest a `<main>` inside `AppPage`'s `<main>`.
