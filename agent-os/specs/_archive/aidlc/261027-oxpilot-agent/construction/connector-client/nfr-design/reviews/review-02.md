### Notes for the conductor (verified clean)

- **Exec-select cancel delivery is sound**: heartbeat arm mid-exec → response `{revoked, cancel}` → `apply_cancels` hits `running`'s kill branch (id inserted before spawn) → `killpg` + `cancelled:mid-flight` report + `settled`. The ≥90s-job liveness decay is closed by the same arm. Matches WF2.5's "cancel arriving on either channel."
- Dispatch table verified row-by-row against BR2.3/BR8.3/BR8.4/NFR4.x: unauthorized/off-pair forbidden → kill+delete+Exit(1) no report; revoked + claim/heartbeat not_found → kill+report+delete+Exit(0); report-404 → drop+continue; bad_input → kill+exit creds kept; disabled/internal → backoff creds kept; rate_limited → sleep hint, never transport-failure.
- `sleep = retry_after (200 body) or Retry-After (204 header)` + 1s floors match BR8.1/BR5.4/NFR3.3 vs shipped `CLAIM_RETRY_AFTER_SECS=0` and the instant-answer cancel path. `HeartbeatOutcome` carries no retry_after — consistent.
- Wire constants re-verified: `CLAIM_WAIT_MAX_SECS=60`, `HEARTBEAT_LIVENESS_WINDOW_SECS=90`, `OUTPUT_MAX=256*1024`, `CLAIM_DEQUEUE_MAX=50`, `PAIRING_CODE_TTL_SECS=600`, `RESULT_MAX=2*1024`, `CONNECTOR_CAPABILITIES` 3-member closed set — all consistent with design pins.
- `settled` eviction rule (evict when the server's cancel set stops re-announcing) is sound: a closed row's id cannot re-enter `cancel_requested` (terminal transitions).
- custody key shape `pilot/<instance>/<connector_id>` rides `keystore::set(instance, token)` as the instance arg — service `ox/pilot/<instance>/<connector_id>`, user `"token"` — consistent with BR2.4.
- Traceability targets resolve to files that cover each family; TS-8 now has real coverage via the new deps table.
