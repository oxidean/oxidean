## Review

Iteration-2 verification of the U3 `agent-runtime` NFR-design set against the current artifacts and shipped code (`crates/oxidean-api-core/src/oxpilot.rs`, `crates/oxidean-api-oxpilot/src/routes.rs`, `session.rs`) plus the upstream pins (rules.md BR1.3/BR3.4/BR4.1/BR5.2–5.4, entities.md ToolSpec/ToolClass/ToolOutput/TurnChain, functional-spec.md proc deltas + C6 provided block, contract-summary.md C6). Fifteen of sixteen prior fixes verified clean: the C6 row now carries the pinned `ToolSpec{name, description, parameters_json}` and `invoke -> Result<ToolOutput, ToolError>`; the slot field conforms to the fd's `tools: Option<Arc<dyn ToolExecutor>>` with the `None`→`NullTools` mapping stated; the provider-absent arm is `oxpilot.disabled`; the two output bounds (32 KiB provider leg / 2 KiB card leg) are split in both performance- and security-design; `emit_terminal` is `async`+`.lock().await` with id-paired `release` and the claim-loss arm; the Q8 answer, shipped helper names, ActiveTurns inventory, entry-held `generation`, BR4.1 placement, `pub(crate)` visibility, `rendered_len`, the `admission_lock` Option-pair proc contract, the abort-drain pin, both traceability repoints, and the PAT-scope erratum (functional-spec.md:228 now pins `auth.pat_scope`) all check out. R-01 is a partial fix: the description column is fully corrected but the same row's component cell still inventories the phantom `ToolCallResult` type — a stale token left behind by the fix, not a wrong contract pin anymore, so the residual rates Minor. Two new Minor items: the `drain_and_chain` pseudo-code wasn't updated for the Option-pair accessor it now pins (and reaches through the map when the task already holds its own entry's lock field), and the questions file's consolidated summary still recites the pre-fix attach order the adopted Q8 answer just corrected.
