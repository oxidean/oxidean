The NFR set is structurally sound — the admission-lock, terminal-CAS, drain/chain, and secret-custody rows all verify against the shipped surfaces (`ActiveTurns`/`ActiveTurn` at crates/oxidean-api-core/src/oxpilot.rs:444-510, `pending_content: String` at :459, `provider_for_turn` at :719, `PING_INTERVAL` 15 s at routes.rs:42, the boot-time `sweep_oxpilot_streaming_messages` at crates/oxidean-api/src/main.rs:139-149, `transcript(user_id, session_id)` at services.rs:329, single-tx `drain_oxpilot_queue_tx` at services.rs:504-527, `oxidean_core::redact` at redact.rs:77, SessionOnly/pat_scope denials pinned by lib.rs:78-89 and the shipped tests). FR6.7's single-replica caveat is carried correctly onto the new in-memory state (NFR11.1/NFR11.2), and the turn_cancel PAT/foreign-session error story (NFR1.1) matches shipped `auth.pat_scope`/`auth.unauthenticated`/`not_found` behavior exactly.

What blocks readiness is constant integrity: two rows pin constants that contradict the reviewed functional-design artifacts they claim to consume — a fabricated `PROMPT_TRANSCRIPT_LIMIT = 50` rows/~64 KiB bound where the fd pins `PROMPT_TRANSCRIPT_MAX_BYTES = 128 KiB`, and `OUTPUT_SUMMARY_MAX = 4 KiB` where the fd pins 2 KiB. Both propagate through traceability.json and the questions file, so code generation would inherit a live spec conflict. The remaining minors are name drift (`TOOL_TIMEOUT`, `PING_INTERVAL_SECS`, `provider_for_turn`), a pinned-log-level contradiction (`info!` vs `debug` terminal), a misattributed contract owner (C6 is U3's, not U5's), several wording imprecisions, and basis-column mis-citations.

### Summary

The runtime seams are real and correctly described — admission lock, terminal CAS, drain/chain liveness, owner-scoped `transcript`, redact-on-wire, the boot sweep, and the SessionOnly/`pat_scope` posture all check out against shipped code. The blocker is constant integrity: `PROMPT_TRANSCRIPT_LIMIT = 50`/~64 KiB and `OUTPUT_SUMMARY_MAX = 4 KiB` fabricate bounds that contradict the reviewed fd's `PROMPT_TRANSCRIPT_MAX_BYTES = 128 KiB` and 2 KiB pins, propagating the conflict into traceability.json and the questions file. Both are one-line-class fixes, but as written a developer cannot satisfy the NFR set without violating the approved functional design.
