> R-01 Reviewer note: `emit_frame` now checks `terminal_sent` INSIDE the `emitted_deltas` lock and returns before the push — check-then-push is atomic against `emit_terminal`'s CAS+push+send under the same lock (runtime.rs:127-135). Post-terminal frames can no longer land in the replay buffer or on fanout; the `message_queue` queued-card push (session.rs:332-340) degrades to the tolerated "dropped card" path its comment already anticipates. New test `emit_frame_drops_after_terminal` (runtime.rs:1506-1526) asserts the buffer ends at the terminal AND the live receiver sees nothing after it. Verified: 32/32 runtime tests pass.; Required action: None — pinned behavior holds in the buffer. (Residual fanout-ordering window tracked as R-06.)

> R-02 Reviewer note: `chat_post`'s residual `svc.drain_queue` `Err` now releases the claim (`release(&session_id, &turn.turn_id)`), error-logs, and returns 500 `oxpilot.internal` — the exact BR4.2 pin and the same shape as the dedupe-recheck `Err` arms (routes.rs:458-471). The user row can no longer mint `seq` ahead of undrained orphans.; Required action: None.

> R-03 Reviewer note: The post-release recheck `drain_queue` `Err` under the admission lock now warn-logs `{session_id}` and `return`s BEFORE the chain decision — the in-turn `outcome.drained` batch is never consulted on a failed recheck (BR4.1). The `sessions()`-unavailable arm (runtime.rs:1076-1088) warn-logs and exits identically; consistent with the pin because `sessions()` is a set-once `OnceLock` (oxpilot.rs:821-831) — it can only `Err` when never installed, which means `run_turn` already failed at runtime.rs:787 and `outcome` is `None`, so no real batch can be stranded. New test `drain_and_chain_recheck_error_with_batch_never_chains` (runtime.rs:2304-2330) builds a REAL non-empty `drained` batch, faults the recheck via session delete, and asserts no successor is claimed — exercises exactly the previously-untested violating path.; Required action: None.

> R-04 Reviewer note: All three adapters now emit `ChatStreamItem::Error{code:"provider_error"}` on bare EOF exactly once (`emitted_done` guards the EOF arm) — `Done` is produced ONLY by the protocol end-marker (`data: [DONE]` / `message_stop` / `done:true`). `run_round`'s `None` arm (runtime.rs:402-405) remains as defense-in-depth for non-conforming providers. Three new wiremock tests (`openai\|anthropic\|ollama_truncated_stream_is_provider_error`, tests/oxpilot_providers.rs:266-341) assert the exact item sequence `delta… → err:provider_error:stream closed before <marker>` — real pinned-behavior assertions, all passing (9/9).; Required action: None — truncated streams now surface `terminal{result:"error", code:"provider_error"}` per C2/C4. (Redundant trailing Error item on the transport-error arm tracked as R-07.)

> R-05 Reviewer note: The `provider.stream(req)` open is now guarded: `is_cancelled()` pre-check (runtime.rs:873-880) then a `select!` racing `turn.cancel.cancelled()` + `sleep_until(deadline)` + the open future. Cancel arm classifies `wall_expired ⇒ turn_timeout` else `Aborted`; the deadline arm stamps `wall_expired`, cancels the token, and answers `turn_timeout`; open `Err` carries the provider's stable code verbatim (BR5.2). A stalled open can no longer hold the claim past an abort/the wall, and an already-dead turn never burns a fresh provider request.; Required action: None.
