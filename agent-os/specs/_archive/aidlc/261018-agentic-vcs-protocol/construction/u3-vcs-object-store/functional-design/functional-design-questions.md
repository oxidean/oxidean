# Functional Design Questions — u3-vcs-object-store

**Unit:** u3-vcs-object-store | **Kind:** library | **Boundary:** `oxidean-vcs` `server` feature — blob bytes on FS + façade row ops; no auth inside; no route code

## Q1 — Crate placement + feature gating
**Decision:** `ObjectStore` lives in `oxidean-vcs` under the `server` cargo feature (ADR-011 — first workspace use of `dep:`-gated features; `default = ["client"]`, `server = ["dep:oxidean-db", "dep:tokio", …]`). Shared dep: `oxidean-core` (error codes/wire types). Server-gated deps (verified against house usage): `oxidean-db`, `sha2`, `tokio` (fs/io), `futures-util` + `bytes` (the `StreamExt<Item = Result<Bytes,E>> + Unpin` stream shape from `lfs/store.rs:35`), `tracing` (GC stats), `chrono` (grace_ts cutoff — `std::time` cannot format the row timestamp). Local `bytes_to_hex` helper (the api-side one is unreachable under the dependency rule). `put` takes the pinned stream shape; `get` returns an opened `tokio::fs::File` (route wraps it — U7's concern). Client feature compiles with none of these (`ox` stays lean).
[Answer]: A — `src/object_store/` under `server`; the enumerated dep set.

## Q2 — PUT ordering + dedup semantics
**Decision:** Server-computed hash (FR11.2 — the client POSTs raw bytes, never names the hash). Stream → `{objects_dir}/tmp/{pid}-{counter}-{nanos}.tmp` (unique tmp name — the digest is unknown until stream end, and per-hash tmp would share one path across concurrent same-hash PUTs) while hashing + counting; per-object cap aborts mid-stream (`vcs.quota_exceeded`, tmp removed — AC3.1.3, never a truncated write); finalize digest → final path `{ab}/{cd}/{hash}` → mkdir shard + rename; then `object_entry.insert_if_absent` + link-ensure step. Re-upload recomputes the same hash, finds the final path present, drops the tmp, and still ensures the link row (dedup must not starve cross-repo attribution). Returns `{hash, Stored|Dedup}` where Dedup = `insert_if_absent` returned false. Empty body ⇒ the legal sha256-of-empty object (`size=0`) — acknowledged, not special-cased.
[Answer]: A — tmp(pid/counter/nanos)→verify→rename→row ordering; dedup still upserts the per-repo link.

## Q3 — Quota enforcement points
**Decision:** Two distinct `vcs.quota_exceeded` denials per the AC3.1.3/AC3.5.3 pinned mapping: (a) per-object streaming cap `OXIDEAN_VCS_MAX_OBJECT_BYTES` enforced while writing tmp; (b) per-repo logical quota `OXIDEAN_VCS_REPO_QUOTA_BYTES` checked via `count_for_repo` before the link insert — skipped when a membership probe says the (repo,hash) link already exists (re-reference adds no bytes). The probe is `vcs_get_object_link(repo_id, hash)` — a sanctioned façade addition under this unit (alternative `live_object_hashes` full-set scan rejected: O(repo objects) per PUT). Concurrent PUTs can both pass the quota check — accepted at single-node scale, recorded as a carried limitation. `size`/`storage_bytes` are `i64` rows vs `u64` config — compared after explicit checked cast.
[Answer]: A — streamed byte cap + probe-gated link-time repo-quota check; two denial sites, one error code.

## Q4 — GC sweep shape + lock
**Decision:** U3 owns the sweep mechanics; U7 owns job spawn/cadence. `gc_once()` = (1) `list_orphaned_before(now - grace)` → per orphan: `vcs_delete_object_if_unlinked(hash)` (sanctioned façade addition — `DELETE … WHERE hash AND NOT EXISTS(link)` shrinks the race window) then delete file — row first so a crash leaves a sweepable file, never a live row over missing bytes; (2) row-less file sweep — **only** shard-shaped `{2hex}/{2hex}/{64hex}` names with mtime past grace and no row (dotfiles, `.gc-lock`, stray files excluded; canonicalize-under-root + no-follow-symlinks per `wipe_lfs_dir_contents` precedent); (3) `*.tmp` sweep past grace. Lock = `create_new` lockfile (skip pass if present); staleness is **age-based** — a lockfile older than `gc_grace_secs` is treated as dead and replaced by `gc_once` itself (the LFS pid is never read back — no liveness precedent exists to clone); `clear_stale_lock()` at boot removes any lockfile outright (fresh boot can't hold one). Per-object failures are logged and skipped — one bad row never aborts the pass (covers the GC-vs-re-reference FK edge: rare, self-healing next pass). Links land inside the changeset create_tx (C6a) covering the PUT→commit race (AC3.5.1/3.5.2).
[Answer]: A — `gc_once()` three-pass sweep + `clear_stale_lock()` boot hook + age-stale lock.

## Q5 — Env-var contract
**Decision:** `ObjectStoreConfig::from_env()` owns names/semantics/defaults verbatim from the frozen contract table: `OXIDEAN_VCS_OBJECTS_DIR=./var/vcs-objects`, `OXIDEAN_VCS_GC_INTERVAL_SECS=3600`, `OXIDEAN_VCS_GC_GRACE_SECS=86400`, `OXIDEAN_VCS_MAX_OBJECT_BYTES=268435456`, `OXIDEAN_VCS_REPO_QUOTA_BYTES=10737418240`. Parsing validates (u64 numerics, dir non-empty); malformed → config error at parse, not silent default. `ObjectStore::new`/`put` `create_dir_all` the objects dir + `gc_once` early-returns on an absent dir (LFS precedents). Host wiring (`.env.example`, docs, compose, railway, factory-reset) is U7's.
[Answer]: A — `ObjectStoreConfig` + `from_env`; the five frozen names/defaults.

## Q6 — Error surface
**Decision:** Internal typed `ObjectStoreError` (hand-rolled enum — no new dep): `QuotaExceeded{scope: Object|Repo}` → `vcs.quota_exceeded`; `NotFound` → `vcs.not_found` (incl. the `io::ErrorKind::NotFound` carve-out — row-exists-but-file-gone or a file deleted between row lookup and open is a domain NotFound, not an Io error); `InvalidHash` → `vcs.invalid_input`; `DbNotConfigured` — driven by an eager `Database::is_skipped()` check at `put`/`get`/`gc_once` entry (facade errors are untyped `String`s — never error-text matching); `Db(String)`/`Io`/`Internal` → host internal (never fabricated as a domain denial). Hash params are bare `&str` re-validated locally (`validate_oid` clone); `ObjectId`/`sha256:` stripping is the U7 boundary's job.
[Answer]: A — typed enum mapping onto the frozen wire taxonomy; `is_skipped()` eager check, io→domain carve-outs pinned.

## Q7 — Sanctioned U2 façade delta
**Decision:** This unit adds two façade methods inside `crates/oxidean-db/src/vcs.rs` (claimed under U3's source manifest — dialect SQL still lives only in `oxidean-db`): `vcs_delete_object_if_unlinked(hash)` (GC pass 1 — conditional `DELETE … WHERE hash AND NOT EXISTS(vcs_object_links)`) and `vcs_get_object_link(repo_id, hash) -> Result<bool>` (Q3 membership probe). Both follow existing façade idioms (`Database`-by-value, `require_pool`, per-dialect rows_affected).
[Answer]: A — two façade additions owned by this unit's change set.
