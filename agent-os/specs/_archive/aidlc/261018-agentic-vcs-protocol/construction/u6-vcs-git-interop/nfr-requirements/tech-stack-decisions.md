# Tech-Stack Decisions — u6-vcs-git-interop

## TD6.1 — One new `server`-gated module + one new dependency edge

`crates/oxidean-vcs/src/git_interop.rs` — `#[cfg(feature = "server")] pub mod git_interop;` wired in `lib.rs`'s server block beside `merge_engine`. **Cargo.toml additions:** `oxidean-git` (the `GitBackend` trait types) and `async-trait` (the `ProtectionChecker` port) — both under the `server` feature's dependency set so `client` stays dependency-free. Verified `oxidean-git` is already a workspace crate; `oxidean-vcs` gains its first crate-edge to it — the dep direction stays `vcs → git` (the trait lives in git; the host injects an impl).

## TD6.2 — `GitBackend` trait extension in `oxidean-git`

Eight new methods on the trait in `crates/oxidean-git/src/backend.rs` with `cli.rs` subprocess impls (u6-claimed files) — **authoritative signatures (supersede the FD table's shorter arities — review-F1):** `cat_commit(repo, sha) -> RawCommit`; `commit_name_status(repo, base: Option<&str>, sha, max_bytes: usize) -> Vec<NameStatusRow>`; `tree_flat(repo, sha, max_bytes: usize) -> Vec<FlatTreeEntry>`; `rev_list(repo, tips: &[String], max: usize) -> RevList`; `verify_commit_oid(repo, rev) -> Option<String>`; `check_refname(repo, refname) -> bool`; `write_object(repo, bytes) -> oid`; `write_commit(repo, entries, parents, author, committer, message) -> oid`. The two `max_bytes` params implement SR6.1's bounded-stdout pin (callers pass `import_tree_max × 1024` / `× 2048`). **`is_ancestor` is NOT added** — it already exists (`backend.rs:735`, `cli.rs:3332` — identical `merge-base --is-ancestor` exit typing; review3-F1). Two modified signatures: `fast_forward_ref`/`force_update_ref` gain an `actor_capability: &str` param replacing the hardcoded `"admin"`; the four production call sites GAIN the `"admin"` literal argument (they pass nothing today — the hardcode lives inside the methods at cli.rs:3275/:3433 — behavioral no-op; four test call sites update the same way). `classify_push_error` is ported into a shared private helper inside `cli.rs` used by both ref-move methods AND `commit_files` (the current methods return raw `Process` errors — dev BLOCKER 3).

## TD6.3 — The `ProtectionChecker` port (ADR-006)

`oxidean-vcs` defines the trait (`check(repo, refname, old, new, actor_capability) -> Result<ProtectionBlockReasons, String>` — real `oxidean-core::protection_types` verdict, NO force param) and `oxidean-vcs` stays host-layout-free — `repo: &Path` arrives per call. `oxidean-api` supplies the concrete impl at dispatch time (u7's wiring); u6 compiles and tests against a mock impl. This is the same injected-trait shape `GitBackend` already follows — the port keeps `oxidean-vcs` free of `oxidean-api`/`oxidean-db`-policy deps while the host closes the loop.

## TD6.4 — u2 schema amendment: migration 0055 ×3 + read/write facade (Q3)

`vcs_derived_index.covering_changeset` becomes nullable: postgres `DROP NOT NULL`; mysql `MODIFY ... VARCHAR(32) NULL` (mysql/0053:78 — `CHAR(29)` is postgres-only); sqlite table-rebuild preserving the FK + `ON DELETE CASCADE` AND recreating `idx_vcs_derived_index_covering` (sqlite/0053:93 — a rebuild drops secondary indexes; pg `DROP NOT NULL` and mysql `MODIFY` keep theirs automatically — devsecops-7). `vcs.rs` changes BOTH sides: `VcsDerivedIndexUpsert.covering_changeset: Option<&str>` (write) AND `VcsDerivedIndexRow.covering_changeset: Option<String>` + `map_index_row!` `try_get` decode (read — NULL rows would fail `vcs_query_derived_index` decode today, review3-F2). Existing callers wrap `Some(...)`; `active`/zero-import `cursor` rows pass `None`. u2-claimed files land in u6's manifest as a recorded deviation — u2's CG binding re-verifies after U6 CG (u4-bigint-deviation precedent).

## TD6.5 — Recorded wire-DTO amendments on u1-claimed `vcs_types.rs` (review3-F3)

Two amendments u6 produces and u7 maps: `VcsGitImportHead.changeset_id` widens to `Option<ChangesetId>` (`null` while a tip is unresolved mid-page) and `VcsGitImportResponse` gains `skipped_tips: u64` (non-commit tip drops surface on the wire, not only in logs). Both recorded in the manifest as deviations; the `Option` widening is a wire-superset (admits `null` a strict old client can't decode) — safe under the monorepo `rpc-gen` lockstep + the SemVer gate (NFR5), not a universal-compatibility claim (devsecops-10).

## TD6.6 — In-crate mirrors of private u4/u5 helpers (no fingerprint-bound edits)

`manifest_diff` (merge_engine.rs:1059), `compose_author` (changeset_store.rs:439-461), the `full_tree` accumulate loop (merge_engine.rs:585 — a private helper, NOT a `ReadIndex` method), and `is_ancestor` semantics over `vcs_changeset_parents` (merge_engine's private helper) are PRIVATE — `git_interop.rs` mirrors each in-crate rather than editing claimed files (review3-F6, devsecops-4; the same discipline u5 used for `is_ancestor_cs` — the export's accumulate runs over the PUBLIC `ReadIndex::tree` pager with the `full_tree` cap-during-accumulation pattern mirrored). `validate_path` (changeset_store.rs:241) IS `pub(crate)` — called directly. `ReadIndex::tree`/`merge_base` are consumed via the public `ReadIndex` surface — no read_index edits.

## TD6.7 — Error channel

One enum `InteropError` per entities.md — no `PartialEq` (u5 convention). `From` impls at consumption sites only: `ObjectStoreError`→per-variant Q7 map (all nine), `ChangesetError`→per Q7, `IndexError`→per Q7 (`CursorMalformed`⇒`ImportState`), `GitError`→classified fixed messages, `io::Error`→`Internal`, facade `String`→`Internal`. Wire mapping pinned in WF6 — u7 consumes variants, never strings.

## TD6.8 — Test posture (NFR10 — same gate as TD5.5)

`cargo nextest run -p oxidean-vcs --features server` + `cargo clippy -p oxidean-vcs --all-targets --all-features` + `cargo nextest run -p oxidean-git` for the backend extensions — zero-test runs are failures. sqlite-backed `GitInterop` tests drive a REAL temp-dir git repo (`git init` + plumbing via the `oxidean-git` CLI impl — Docker-resident git, matching the user's docker-first testing preference): `import_chain` linear + merge + rename + gitlink-skip + non-UTF8-path refusal + ident-sidecar round-trip; cursor resume + `last_oid` continuity + byte-cap refusal + forged-cursor `skip > len` `ImportState` (devsecops-M1) + dash-led `from`/rev `InvalidInput` (the argv-injection guard); `lazy_import` multi-page loop + done∧unlinked `Internal` + direct-tip-seed (a branch named the 40-hex target must not shadow); non-commit tip drop counted in `skipped_tips`; claim contention — second `active` claim `ImportState`, nonce-mismatch release skipped, TTL reclaim; export ff + force + unlinked-tip `RefConflict{None}` + linked-non-ff `RefConflict{Some}` + hook-denied `Forbidden{push_hook}` + same-oid alias + raced-push CAS `Conflict`→re-read; `classify_push_error` behavior on the two MODIFIED move methods (`Denied`→push_hook, `Conflict`→RefConflict — not just the new plumbing); the 0055 NULL-covering rows round-trip through `vcs_query_derived_index` (devsecops-8: every one of these paths is named, not covered by blanket wording). Backend tests in `oxidean-git` cover each new plumbing method against temp repos (folded-header `cat_commit`, `-z` rename order, `rev_list` parents-first reversal, `verify_commit_oid` tag peel, stdout `max_bytes` kill).
