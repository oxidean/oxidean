## Review

**Verdict:** NOT-READY
**Stage:** functional-design
**Unit:** u6-vcs-git-interop
**Iteration:** 1
**Reviewer:** aidlc-architecture-reviewer-agent

### Findings

- [BLOCKER] `covering_changeset=""` on the `active`/`cursor` marker rows violates a hard foreign key — `vcs_derived_index.covering_changeset` is `NOT NULL REFERENCES vcs_changesets(id) ON DELETE CASCADE` in all three dialects (migrations/sqlite/0053:72; mysql/0053 `fk_vcs_didx_cs`; postgres/0053:71). Every existing writer passes a live changeset id; the `active` upsert runs before any changeset exists on a fresh repo → every `claim()` fails Internal; `cursor` on a zero-import page likewise has no cs. Fix: coordinate a u2 schema amendment (nullable `covering_changeset` or drop the FK — 0055 migration + `VcsDerivedIndexUpsert.covering_changeset → Option`) — "no facade edits" cannot hold for marker state; alternatively sanction a different store.
- [BLOCKER] Import processes `rev_list` in the wrong direction: `--topo-order` emits children before parents, but WF1.6/WF2.6 iterate forward while WF3.2 + BR6.5 require parents linked earlier — first non-root commit's `link_lookup` misses → Internal. Fix: pin `RevList.oids` as parents-first (reverse in the backend — `--reverse`+`--max-count` truncates the wrong end; bounded full list then in-crate reverse); `skip`/`last_oid` index the parents-first order.
- [BLOCKER] The ff gate uses the wrong-direction lookup: WF4.4/Q5.4/BR6.16 read `linked_lookup(old_oid)` — but `linked_lookup` queries `linked:{cs}` keyed on changeset ids; a git oid can never hit → every export onto an existing branch fails as "git-only tip ⇒ RefConflict". Fix: `link_lookup(old_oid)` (forward git_oid→cs) to obtain `old_cs`; keep the `old_cs ∈ set` clause (covers healed-half-pair: forward link present, `linked:` absent → re-mints identical oid, `link_insert` false → verify-equal → `linked:` upsert heals).
- [MAJOR] Cursor advance arithmetic inconsistent: `skip: skip+imported` vs `last_oid: batch.last()`. Fresh-conversion counting under-advances `skip` while `last_oid` records the window end → resume's continuity check misfires; consumed counting over-reports `imported`. Fix: `skip += consumed_window_len`, `last_oid = list[new_skip-1]`; `out.imported` = fresh conversions only.
- [MAJOR] `heads[].changeset_id` can miss mid-import: `--topo-order` doesn't bound all tips inside the first `limit` entries (independent branch tips interleave by commit-date priority; `limit < #tips` guarantees misses) → `link_lookup(tip)` `None` on a non-optional field; contract pins `{name,git_oid,changeset_id}`. Fix: `changeset_id: Option<ChangesetId>` + contract errata note (`changeset_id|null` while unresolved), or emit `heads` only when `done`.
- [MAJOR] A denied export leaves rows — "no rows" is false: `link_insert` + `linked:` write during chain-write before the verdict; surviving `linked:` anchors point at unreferenced minted objects; once `git gc` prunes them, a later export mints children with `commit-tree -p <missing>` → Internal. Same hole for anchors whose ref was deleted then gc'd. Fix: probe anchor object existence during the chain walk (`verify_commit_oid`/cat-file -e; missing ⇒ treat as unlinked so re-mint heals) and correct the "no rows" claim — or defer link writes to post-move.
- [MINOR] `ProtectionChecker::check` carries no force/intent dimension: the real evaluator splits Push vs ForcePush (`allow_force_pushes` checked only under ForcePush, protection/mod.rs:216-229). Fix: add `force: bool` (or intent enum) to the trait signature.
- [MINOR] The `ChangesetError` bridge invents `QuotaExceeded`: the enum is `ParentNotFound|ObjectNotFound|ChangesetNotFound|InvalidInput|Internal|DbNotConfigured` (changeset_store.rs:56-74) — no quota variant. Fix: map `ParentNotFound`/`ChangesetNotFound`→`NotFound`, `ObjectNotFound`→`Internal`, drop the phantom arm.
- [MINOR] `release` is unconditional `{idle}` upsert: a claim *loser's* release can overwrite the *winner's* fresh `active` marker. Fix: nonce-verify before release; skip release when the marker carries another nonce.
- [MINOR] `tree_flat` output uncapped — O(tree-size) entries per commit while `import_tree_max` bounds only name-status rows. Fix: `flat.len() > import_tree_max ⇒ TooLarge`. Also: tag tips peeling to non-commit drop + warn, not error.
- [MINOR] Same-oid export alias: two distinct changesets can mint the same git oid when tree+parents+idents+message collide — `link_insert` false+divergent stored id is an alias, not corruption. Fix: on export, that case still writes `linked:{ours}→oid` and proceeds.
- [NIT] Pin gaps: (a) `from`+`cursor` co-supply — pin "cursor authoritative, `from` ignored". (b) `TipSnapshot.name` = resolved display name. (c) `rfc3339(a.unix)` unrepresentable ⇒ `InvalidInput` (no unwrap-panic). (d) refusal inventory under-lists email `<>`, control-byte, `.`-segment path refusals (compose_author:446-455, validate_path:241-266). (e) >250k single-cone can never import — restate the mitigation honestly. (f) dash-led raw `from` parses as a flag → reject or `--` separator. (g) concurrent `git gc --prune` can reap minted-unreferenced objects between write and move (same exposure as `commit_files`) — note it. (h) empty-set export (`head` already linked ⇒ `commits_count=0`, tip=anchored oid, move still runs) — state it.

### Summary

Sound convergence architecture, but three implementation-blocking defects — the FK-breaking `""` marker row, the reversed rev-list processing direction, and the wrong-direction ff-gate lookup — plus six majors (cursor arithmetic, `heads` miss, denied-export leftover rows, force-intent, phantom bridge arm, release race, flat cap) need resolution before code generation.
