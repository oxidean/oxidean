### Summary

The decomposition itself is sound: all 13 component names are unique, every entity has exactly one owner with a declared identifier, all `references.entity` targets exist under their stated `owned_by`, infra is correctly modeled as `external_dependencies`, the Mermaid is consistent with the declared edges, and traceability.json covers all story IDs (US1.1–US8.6 with US7.3 correctly absent) against real component names. All five mob blockers are verifiably resolved in the bytes — the two-case flag gate, global-CAS `ObjectEntry`+`ObjectLink` with GC-computed referenced-ness, the `client`/`server` feature split (ADR-011), the activity seams (`VALID_PUSH_TYPES` extension via oxidean-core constants, push-shaped `insert_repo_activity` handoff, `actionCopy`/`commitHref`/filter-chip ownership under VcsWebSurfaces), and the archived-denial split (host resolves the bit; write-class dispatch arms call `ensure_not_archived`, verified at `acl.rs:436`). Spot-checks confirmed every claimed seam exists: `Arc<dyn GitBackend>` AppState slot (`app.rs:62`), `DefaultBodyLimit` 2 GiB precedent (`app.rs:389`), `API_PREFIXES` includes `/api/` (`proxy.rs:17`), `SessionOnly` fail-closed (`proc_classes.rs:367`), private `VALID_PUSH_TYPES` (`activity.rs:20`), `error_exit_code` match list (`rpc.rs:52`), `fg_repo_access_check` owner/name convention (`mcp.rs:1041–1050`), hook-driven `fast_forward_ref`/`force_update_ref` vs bare `update_ref` (`cli.rs:3399/3245/3449`), and ×3 migration trees. Two majors block sign-off: the machine-readable YAML catalogue fails to parse (R-01) and the FR9.4 lazy-import path is unowned (R-02); fix both plus the minor catalogue-consistency items before advancing.
