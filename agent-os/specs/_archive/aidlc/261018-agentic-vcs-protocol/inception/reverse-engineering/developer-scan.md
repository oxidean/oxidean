### APIs Discovered
- Typed JSON RPC — `crates/oxidean-api/src/rpc.rs` + `src/app.rs` — 306 procedures (the `PROCEDURES` const at `rpc.rs:150-457` is the manifest source of truth; e.g. `system.*`, `auth.*` incl. 2FA, `user.*`, `admin.*`, `org.*`, `repo.*` (~110 procedures: browse/tree/blob/commits/branches/files/lfs/mirror/protection/collaborators/invites/quota/actions/secrets/statuses), `issue.*`, `pull.*`, `release.*`, `webhook.*`, `label.*`, `packages.*`, `pat.*`, `oauthApp.*`, `oauth.*` device, `sshKey.*`, `gpgKey.*`, `email.*`, `notification.*`, `search.global`, `invites.*`). Transport: `POST /api/rpc` + `GET /api/rpc/ws` (WS re-resolves credentials per frame), envelope `{procedure, input}` → `{ok, data}` | `{ok:false, error:{code,message}}`; required header `Oxidean-RPC-Version` (SemVer wire gate, `0.1.0` today, legacy `"1"` accepted). Registration = add name to `PROCEDURES` + a match arm in `dispatch()` + handler module; errors map to HTTP status in `rpc_status()`. PAT Bearer callers are scope-gated at dispatch via `pat::bearer::authorize_rpc` + `oxidean_core::proc_classes` (fail-closed: unlisted procedures = SessionOnly).
- REST facade — `crates/oxidean-api/src/rest/` mounted at `/api/v1` — 65 `RouteDef` rows across `rest/{repos,issues,pulls,orgs,users,releases,statuses,admin}.rs` (+meta). Each route translates to an RPC procedure and re-runs `rpc::dispatch` — no duplicated business logic. `spec.rs` is a single-source route table that also generates OpenAPI; `GET /api/v1/openapi.json` + Swagger UI at `/api/v1/docs` (`utoipa-swagger-ui`); `docs/openapi.yaml` is generated by `openapi-gen` + `make openapi-sync-check`.
- MCP server (instance) — `crates/oxidean-api/src/mcp.rs` at `POST /api/mcp` — JSON-RPC 2.0 streamable-HTTP in JSON mode (no SSE; GET→405; no `Mcp-Session-Id`). Methods: `initialize`, `ping`, `tools/list`, `tools/call`, `resources/list` (empty), `resources/templates/list`, `resources/read`, `prompts/list` (empty), notifications→202. 20 tools (`repo_list`, `repo_get`, `repo_tree`, `issue_list`, `issue_get`, `issue_create`, `issue_comment`, `issue_list_comments`, `pull_list`, `pull_get`, `actions_list_runs`, `actions_get_run`, `workflow_templates_list`, `workflow_template_get`, `workflow_create`, `packages_list`, `search_repos`, `search_issues`, `search_pulls`, `search_code`) — thin wrappers mapping to typed RPC procedures via `build_rpc_input`; resource URI templates `oxidean://repo/{owner}/{name}/{blob,issue,pull}/…`. Auth: session cookie OR `Bearer` PAT (`oxidean_pat_`/`oxidean_fg_`) OR OAuth `oxidean_oat_` token; instance gate `OXIDEAN_MCP_ENABLED` + `admin.mcp.*` DB override; domain denials surface as `isError` tool content. RFC 8414/9728 well-known docs on the router.
- Git Smart HTTP — `crates/oxidean-api/src/routes/git_smart_http.rs` + `src/git/http_backend.rs` — `GET /{owner}/{repo}.git/info/refs`, `POST …/git-upload-pack`, `POST …/git-receive-pack`: HTTP Basic with password = PAT/OAuth/job-token (session cookies never authorize git, D-12); spawns `git-http-backend` CGI (`GIT_PROJECT_ROOT=OXIDEAN_REPOS_DIR`, `GIT_PROTOCOL` v2 passthrough, `GIT_CONFIG_*` `uploadpack.allowFilter`, `OXIDEAN_*` protection env). ### Technical Debt Signals
- **`rpc_gen.rs` is a hand-maintained mirror**: the ~6,100-line `crates/oxidean-api/src/bin/rpc_gen.rs` embeds the entire TS client template with per-procedure typed methods; it is NOT derived from `PROCEDURES`/`rpc.rs` automatically — every new RPC requires a manual template edit, guarded only by `make rpc-sync-check` + the `procedures_list_matches_dispatch` scan test. Adding a whole new `vcs.*` procedure family means a large template addition (or first refactoring codegen to emit from metadata).
- **Same for REST/OpenAPI**: new RPC procedures do not appear in `/api/v1` or `openapi.yaml` unless a `RouteDef` row is added by hand in `rest/spec.rs` tables.
- **Migration triple-write**: every schema change must be hand-ported to `migrations/{postgres,mysql,sqlite}/` (only filename parity is enforced by test; SQL bodies can drift semantically). 52 files × 3 dialects today.
- **Monolith hotspots**: `crates/oxidean-db/src/lib.rs` 4,941 LOC; `crates/oxidean-cli/src/{args,commands}.rs` ~4,155/4,053 LOC each (hand-rolled parser, no clap); `crates/oxidean-git/src/cli.rs` 5,943 LOC; `crates/oxidean-api/src/{rpc.rs 1,946, mcp.rs 1,820}`; `packages/api-client/src/index.ts` 6,009 LOC generated.
- **Dual notification modules** (`crates/oxidean-api/src/notify/` fan-out vs `notification/` RPC) — intentional split but confusingly named.
- **Deferred backends documented**: `GixGitBackend` (gitoxide) explicitly documented-but-unimplemented in `oxidean-git` — the trait seam exists precisely for this kind of swap.
- **Grep-debt is minimal**: 5 TODO/FIXME/HACK across all crates, 0 in `apps/web/src`, 0 `todo!`/`unimplemented!` — hygiene is good.
- **Verify-marker**: `docs/API.md` carries one `<!-- VERIFY: … -->` comment (production base URL).
- **Optional coverage gap**: Rust coverage is collected but not gated (`docs/TESTING.md` residual).
- **Per-process limiters/stores** (`login_begin_limiter`, `git_auth_limiter`, `lookup_limiter`, `two_factor_store`, `pending`, `SshAuthLimiter`) live in `AppState` — fine single-node, but any new server component joining the API process inherits in-memory-only state (no horizontal scaling story).

## Handoff Summary
- **Intent-relevant finding** (most relevant to the agentic-VCS intent):
  1. **The `GitBackend` trait is the canonical seam for "another VCS engine"** — `crates/oxidean-git/src/backend.rs:410-771` defines all forge git ops behind `Arc<dyn GitBackend>` on `AppState` (`app.rs:62`, set at `app.rs:186`); a sibling VCS crate can either implement an analogous trait or expose its own `Arc<dyn …>` slot on `AppState` without touching `repo/*` handlers.
  2. **Adding a new network surface is routinized**: mount Axum routes in `router_with_state` (`crates/oxidean-api/src/app.rs:268-407`), register RPC procedures by (a) adding names to `PROCEDURES` (`rpc.rs:150-457`), (b) a `dispatch()` match arm, (c) types in `oxidean-core`, (d) a `PatProc` class in `oxidean-core/src/proc_classes.rs` if token-callable, (e) the generated-client template in `bin/rpc_gen.rs`, (f) optional `RouteDef` rows in `rest/spec.rs`. For non-RPC transports, the Smart HTTP (`routes/git_smart_http.rs`) + LFS (`routes/git_lfs.rs` + `lfs/`) + SSH (`ssh/server.rs` in-process russh listener spawned from `main.rs:83`) + packages (`packages/*.rs` `.nest()`ed routers) patterns show every edge flavor: Basic-PAT, Bearer, pubkey, per-repo enable flags, quotas, GC jobs.
  3. **MCP for the new VCS gets a proven shape**: `crates/oxidean-api/src/mcp.rs` is a self-contained streamable-HTTP JSON-RPC server mapping `tools/call` → typed RPC procedures with `Access` gates (RepoRead/RepoWrite/Identity) and PAT/OAuth/session auth already resolved (lines 227-315, `tool_defs()` ~612, `call_tool`, resource templates ~1226). The intent asks for "an MCP server" in the new crate — the existing endpoint is a single-file model to mirror, and `ox mcp` (CLI `src/mcp.rs`) already knows how to install/point clients at endpoints.
  4. **CLI subcommands**: `ox` uses a hand-rolled parser (`args.rs` `Command` enum ~262 + per-command `required_procedures` gating via `system.manifest`, `commands.rs:481`) — a new `ox vcs …` family slots in as new enum variants + help-table rows; `ox api <procedure>` already exists as a raw-RPC escape hatch (`args.rs:3386`).
  5. **Persistence**: new tables need SQL ×3 dialects + a `Database` method module in `oxidean-db` + row types; filename parity test enforces all three. Blob/object storage precedent: LFS (`OXIDEAN_LFS_DIR`, OID-sharded + refcount) and packages (`OXIDEAN_PACKAGES_DIR`, content-addressed) both show the dir-layout + quota + GC-job pattern a new VCS object store would clone (`app.rs:95-152` env-dir pattern, `jobs/mod.rs` spawn).
  6. **Boot/plumbing**: `main.rs:7-128` shows the exact order — version gate → CORS → `Database::from_env` → auto-migrate → seed → spawn aux listeners (SSH) → `AppState::new` → background jobs → `router_with_state` → `axum::serve`. A side-by-side protocol server that "runs alongside git on the server" most naturally spawns from the same `main` (like `ssh::maybe_spawn_from_env`, `main.rs:83`) or mounts alongside the `.git` routes on the same Axum port.
  7. **Edge parity is a hard requirement**: any new path prefix must be added to Traefik labels (`docker-compose.yml` api service), Caddyfile matchers (`deploy/cloud/Caddyfile`), AND `oxidean-web`'s `API_PREFIXES`/`is_api_git_path` (`crates/oxidean-web/src/proxy.rs:16-86`) — three-place sync, each with tests (e.g. `proxy.rs` prefix-boundary tests).
- **Risks / follow-up**:
  - `PROCEDURES`/dispatch/rpc_gen/RouteDef/proc_classes are 5 parallel registration surfaces a new RPC family must update (sync-tested, but noisy); consider grouping new procedures under one domain module like `crate::vcs` analogous to `crate::repo`.
  - Smart HTTP route pattern `/{owner}/{repo_git}` is greedy at the top level — a new protocol sharing the URL space (e.g. `/{owner}/{repo}.vcs` or a `/vcs/…` prefix) must be checked against `is_api_git_path` semantics (`proxy.rs:82`) and Traefik `PathRegexp` before routes are designed.
  - PAT scope model is fail-closed for new procedures (`SessionOnly` default) — an agentic-VCS protocol intended for machine callers MUST get explicit `proc_classes` entries or tokens can't call it.
  - The AuthKit: session cookie never authorizes git transports today (D-12); a new protocol can choose its own auth envelope but should reuse `sha256` PAT lookup + `FailedAuthLimiter` (`pat/rate_limit.rs`) rather than minting a parallel credential type.
  - `oxidean-db` `Database` is `Clone` and its `Database::skipped()` no-DB mode exists — new crate code should accept `Database` by value/clone, not `&DbPool`, and tolerate `is_skipped` (boot without `DATABASE_URL` is a supported mode, `main.rs:52-54`).
  - WebSocket precedent exists at `/api/rpc/ws` with per-frame credential re-resolution (`app.rs:802-844`) — relevant if the agentic protocol is streaming.
  - Existing codekb store at `aidlc/spaces/default/codekb/oxidean-app/` is marked STALE per intent memory.md; this scan's `./` deep coverage supports a `kind: full` scope block on rewrite (record scope: `./` = whole repo).
