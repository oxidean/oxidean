## B. Repo-page / HI structure (Header–Info chrome + IA)

**Interpretation of “HI” (issue comment):** repo **Header/Info chrome** — the title + visibility badge + description + horizontal tab nav implemented as `RepoChrome`, plus how that chrome is composed across routes. Closely overlaps **information architecture** problems called out as “not intuitive.”

### B.1 Relevant files (absolute paths)

**Chrome / shell**

- `/home/jesse/wsl-projects/personal/typescript/oxidean/apps/web/src/components/repo/repo-chrome.tsrx` — Header (owner/name + badge) + Info (description) + tab nav (`Code|Commits|Branches|Tags|Issues|Releases|[Settings]`). **`active` union has no `"packages"`.**
- `/home/jesse/wsl-projects/personal/typescript/oxidean/apps/web/src/components/repo/repo-page-shell.tsrx` — shared `max-w-6xl` shell only.
- `/home/jesse/wsl-projects/personal/typescript/oxidean/apps/web/src/components/repo/repo-store-provider.tsrx` — SSR seed / hydrate keying.
- `/home/jesse/wsl-projects/personal/typescript/oxidean/apps/web/src/routes/$owner.$repo.tsrx` — layout: shell + store + Outlet; **does not render `RepoChrome`.**

**Route tree (flat TanStack file routes under `apps/web/src/routes/`)**

| Area | Paths |
|------|--------|
| Owner layout | `$owner.tsrx` (Outlet only), `$owner.index.tsrx`, `$owner.packages.tsrx`, `$owner.settings*.tsrx` |
| Repo layout | `$owner.$repo.tsrx` |
| Code browse | `$owner.$repo.index.tsrx`, `.tree.$`, `.blob.$`, `.blame.$`, `.commits.$`, `.commit.$sha`, `.branches`, `.tags`, `.compare.$` |
| Issues | `$owner.$repo.issues.tsrx` (Outlet-only layout), `.issues.index`, `.issues.new`, `.issues.$n`, `.issues.labels` |
| Releases | `$owner.$repo.releases.tsrx` (Outlet-only), `.releases.index`, `.releases.new`, `.releases.$tag` |
| Packages | `$owner.$repo.packages.tsrx` — **standalone page, no chrome** |
| Settings | `$owner.$repo.settings.tsrx` (collaborators, LFS, rename/transfer panels inline) |

### B.2 Current IA / HI problems

1. **Chrome not in the layout.** Every leaf remounts `<RepoChrome … active="…" />`. Parent `$owner.$repo.tsrx` only provides shell + store. Issues/releases parents are empty Outlet shells. Nav highlight and header markup are copy-pasted ~15+ times → easy drift (already visible with packages).
2. **Packages orphaned from HI.** Route exists at `/$owner/$repo/packages` with its own title/`max-w-6xl` and **no** `RepoChrome` / `RepoPageShell` from layout; chrome has no Packages tab and no `active: "packages"`. Users cannot discover the page from repo nav.
3. **Inconsistent nesting model.** Issues/releases use layout+index; code/settings/packages do not. Flat filenames (`$owner.$repo.issues-releases.layout.integration.test.ts` as a raw-source Outlet check) paper over the inconsistency rather than documenting a clear folder IA.
4. **Settings as a single mega-route.** Collaborators, LFS, rename/transfer live in one `$owner.$repo.settings.tsrx` with separate integration tests — harder to reason about than GitHub-like subpages.
5. **Owner vs repo packages split.** `$owner.packages.tsrx` (fuller UI + delete) vs `$owner.$repo.packages.tsrx` (minimal list) with different chrome conventions.

## E. Recommended inserted GSD phase

### Phase **11.1** — `quality-hardening` *(INSERTED between 11 Issues and 12 Pull Requests)*

**Slug:** `11.1-quality-hardening`  
**Goal:** Make forge-core (09–11, 14, 15, 20) trustworthy under CI: fix broken/incomplete UI IA, expand unit→integration→hydration/e2e coverage with **weighted coverage gates**, and reconcile GSD verification docs with reality — **before** Phase 12 PR objects land on the same chrome.

**Depends on:** Phases 09–11, 14, 15, 20 code on main/forge-core  
**Blocks:** Phase 12 discuss/execute (or at least Phase 12 UI plans)

### Work packages (prioritized)

#### P0 — Stop the bleeding

1. **Repo HI / chrome refactor** — Lift `RepoChrome` into `$owner.$repo` layout (or shared outlet wrapper); add Packages tab + `active`; route packages through same shell; reduce leaf duplication.  
2. **Coverage toolchain + docs** — Vitest coverage (v8) for unit+integration; rustc/llvm-cov or cargo-llvm-cov for crates; document commands in `docs/TESTING.md`; add CI job(s) with **weighted** thresholds (proposal below).  
3. **Hydration / stack-browser matrix (auth → forge)** — Restore a sustainable browser project (fix stack-browser or reintroduce component e2e carefully); first flows: repo code home, issues CRUD, releases CRUD, packages list, SSH keys, org members.  
4. **GSD truth pass** — Write/repair `09-VERIFICATION.md`; flip `09-VALIDATION` Nyquist; annotate 11/15/20 VERIFICATION with known stubs (pr_stub, referrers, packages chrome); update `STATE.md` / ROADMAP notes for partial UX.

#### P1 — Coverage depth

5. Route integration tests for **login / verify / profile / invites** and code browse leaves (tree/blob/branches/tags) beyond Wave 0 export checks.  
6. Promote key `make smoke-git-*` / `smoke-packages` into CI (nightly or PR-labeled) so protocol regressions don’t rely on happy-dom alone.  
7. Close Phase 10 deferred slug dual-check on signup/rename.  
8. Expand api-client tests beyond single `index.test.ts` for new forge RPC shapes used by UI.

#### P2 — Polish / ratchet

9. Split repo settings into sub-routes matching org settings pattern.  
10. Folder IA for routes (`routes/repo/...`) if TanStack file routing allows without breaking gen — or document conventions in `docs/CODE_PRACTICES.md`.  
11. Raise coverage floors gradually; add mutation/interaction coverage weight higher than line % alone.  
12. Re-enable web lint (Biome/ESLint) once quality phase stabilizes.

### Suggested CI weight model (starting point)

| Layer | Weight | Initial gate idea |
|-------|--------|-------------------|
| Unit (web + rust lib units) | 25% | Lines ≥ existing baseline − 0; fail on drop |
| Integration (happy-dom + rust `tests/`) | 40% | Critical modules: issues, packages, releases, lfs, ssh, orgs |
| E2E / hydration (stack-browser + selected smokes) | 35% | Required flows checklist green (binary), plus optional % later |

Implement as: separate coverage artifacts + a small aggregator script that fails CI if weighted score &lt; threshold (e.g. 0.70 initially, ratchet up).
