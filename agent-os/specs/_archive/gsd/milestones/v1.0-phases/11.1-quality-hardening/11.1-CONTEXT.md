## Locked decisions

### D-QH-01 — Repo chrome (HI)

Lift `RepoChrome` into `$owner.$repo` layout (or one shared outlet wrapper). Leaves stop remounting chrome. Add Packages to tab nav + `active: "packages"`. Wire `$owner.$repo.packages` through the same shell.

### D-QH-02 — Coverage layers & weights (initial)

| Layer | Weight | Gate idea |
|-------|--------|-----------|
| Unit (web + rust lib units) | 25% | Baseline floor; fail on drop |
| Integration (happy-dom + rust `tests/`) | 40% | Critical modules: issues, packages, releases, LFS, SSH, orgs |
| E2E / hydration (stack-browser + selected smokes) | 35% | Required-flow checklist green; optional % later |

Document commands and weights in `docs/TESTING.md`. Aggregator script may start with weighted score ≥ ~0.70 then ratchet.

### D-QH-03 — Browser / hydration strategy

Prefer extending existing `apps/web/e2e/stack-browser/` over reintroducing the removed Playwright component project that broke Vitest collect on GHA. First flows: repo code home, issues CRUD, releases CRUD, packages list, SSH keys, org members.

### D-QH-04 — Protocol smokes in CI

Promote key `make smoke-git-*` / `smoke-packages` into CI (PR job and/or nightly) — not happy-dom only.

### D-QH-05 — GSD truth

Write/repair `09-VERIFICATION.md`; make `09-VALIDATION` Nyquist-honest. Annotate 11/15/20 VERIFICATION with known stubs. Do not “fix” stubs by inventing Phase 12 behavior.

### D-QH-06 — Settings / route IA (P2)

Split mega `$owner.$repo.settings` into sub-routes only after P0 chrome + e2e land. Folder IA / lint re-enable are P2 polish.
