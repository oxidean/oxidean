<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser/client → `POST /api/rpc` `system.db_probe` | Unauthenticated in Phase 2 (auth gate explicitly deferred by CONTEXT) |
| Env (`DATABASE_URL`, `OXIDEAN_DB_DIALECT`, `OXIDEAN_AUTO_MIGRATE`) → API startup | Operator config controls schema mutation on boot |
| Rust types → generated TS client | Drift here silently breaks consumers |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-06 | Information disclosure | `system.db_probe` error payload | mitigate | Handler returns the fixed code `db.probe_failed` with a generic message; the detailed (already URL-redacted) error goes to `tracing::error!` only, never into the RPC response body |
| T-02-07 | Denial of service | unauthenticated probe writes | accept | Probe is a bounded single-row upsert on `id = 1` — no row growth, no user input; auth gating lands with the system-admin dashboard (CONTEXT deferred). Recorded as an accepted risk in `02-SECURITY.md` |
| T-02-08 | Tampering | auto-migration on boot | mitigate | `OXIDEAN_AUTO_MIGRATE=false` disables boot-time schema mutation and requires the explicit `make db-migrate` path (D-07); migration failure aborts startup instead of serving on an unknown schema |
| T-02-09 | Spoofing | operator misreads which database was hit | mitigate | `dialect` is read back from the `instances` row itself (not from process env), so the response reflects the database actually written (D-10) |
| T-02-10 | Tampering | generated client drift | mitigate | Existing `make rpc-sync-check` / CI `rpc-sync` job extends automatically to the new procedure |
</threat_model>

```rust
"system.db_probe" => match db.probe().await {
    Ok(result) => RpcResponse::ok(result),
    Err(e) if e == "database not configured" => RpcResponse::err(AppError::new(
        "db.not_configured",
        "no database configured for this instance",
    )),
    Err(e) => {
        tracing::error!("db probe failed: {e}");
        RpcResponse::err(AppError::new("db.probe_failed", "database probe failed"))
    }
},
```

   The detailed error stays in the server log; the wire response carries a stable code only (T-02-06). Add `tracing` to `oxidean-api` deps if not already present.
