<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Anonymous reset request → user directory | Enumeration risk |
| Reset redeem → password + session | Account takeover if token weak / reusable |
| Reset success → session cookie | Must not leave old sessions valid |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-09 | Information disclosure | `auth.request_password_reset` | high | mitigate | Always identical success after email normalize; send mail only for local-password users; avoid early-return timing skew (D-28) |
| T-05-10 | Elevation of privilege | `auth.reset_password` | high | mitigate | Same hash-at-rest tokens, TTL, rate limits, attempt caps as verify; single-use; password min 8 via existing Argon2 helpers |
| T-05-11 | Elevation of privilege | post-reset sessions | medium | mitigate | On success: update password_hash, revoke_all sessions, mint fresh session cookie (D-27); honor product lock over OWASP re-login preference |
| T-05-12 | Information disclosure | SSO-only reset | medium | mitigate | No mail on request for SSO-only; redeem error uses stable SSO copy class — never reveal on request whether email existed |
</threat_model>
