Include the wiring checklist every prior dir required: `docker-compose.yml` env block + `./var` bind (lines 69–72), `docs/DEPLOYMENT.md` volume table (139–140), `.railway/railway.ts` (68–69), CONFIGURATION.md "do not fail boot if unset" list (282) + env→code table (299), and the "must not share dir" caveat (D-PKG-07, CONFIGURATION.md:51).

2. [blocking] **Objects dir missing from lifecycle/wipe paths.** `VcsPersistence` behaviour covers repo-row cascade, but the dir never appears in lifecycle text. Factory reset wipes `OXIDEAN_REPOS_DIR` **and** `OXIDEAN_LFS_DIR` today (CONFIGURATION.md:127 via `wipe_lfs_dir_contents`, `jobs/lfs_gc.rs:101`); orphan reconcile scans only `repos_dir` (`jobs/reconcile.rs`). A "Database and repositories" reset that skips `OXIDEAN_VCS_OBJECTS_DIR` leaves every blob a row-less file invisible to DB-driven GC — permanent silent leak. Add the dir to the reset sweep or pin a disk-scan GC.

3. [suggestion] **`ObjectEntry` identity contradicts shared-CAS + per-repo quota.** Entity is identified by bare `hash` yet carries attribute `repo_id` (components.md ObjectStore entities + Entity Ownership table). FR1.5 pins "shared refcounted CAS"; repo size limits need per-repo accounting. LFS solves this with a link table + logical-bytes-per-owner (`crates/oxidean-db/src/lfs.rs:443–488`). Pin `repo_id + hash` rows (per-repo, logical charging) or a global row + attribution — GC scoping and quota math both hinge on the choice.

4. [suggestion] **Refcount representation and its transaction edge are unpinned.** A stored `refcount` drifts when repo-delete cascades FileChange rows (AC1.3.1) with no decrement path → objects leak past grace forever. LFS precedent computes referenced-ness via LEFT JOIN at GC time (`lfs.rs:517–574`, `list_unreferenced_lfs_oids`) — self-healing under cascade. Pin computed-at-GC or the decrement rule. Separately, the ChangesetStore→ObjectStore `depends_on` lists only "verify blob hashes"; the refcount mutation must ride the same create tx (AC3.5.2, ADR-001 single-tx consequence) and the edge should say so.

5. [suggestion] **GC disk-side gaps cloned from the LFS pattern.** (a) `list_unreferenced_*` is row-driven → bytes on disk with no row (crash between rename and row insert) are never found. (b) Crashed PUTs leave `*.tmp` files (`lfs/store.rs:53`) with no sweeper. (c) `.gc.lock` uses `create_new` with no staleness check (`lfs_gc.rs:42–50,84–99`) — a crash holding it disables GC until manual `rm`; restarts don't clear it. Pin PUT order temp→rename→row ("row implies file"), a tmp/row-less sweep cadence, and boot-time lock clear.

6. [suggestion] **Same-parent commits vs `DerivedIndex` unique-key collisions.** AC2.3.1 says concurrent children of one parent always succeed; two such commits updating the same `repo_id + kind + key` index rows (e.g. path-history head for the same path) can collide inside their create txs. Pin upsert/merge semantics for index maintenance or a defined retry, else AC2.3.1 is violated at the DB layer. Adjacent honesty note: on SQLite the single writer serializes commit txs regardless — NFR2 "lock-free" is correctness, not parallelism.

7. [suggestion] **`git_export` branch move must name the safe port.** `fast_forward_ref`/`force_update_ref` (`crates/oxidean-git/src/cli.rs:3399–3440, 3245–3296`) push through a temp worktree → receive-pack → `hooks/update` + git's atomic FF ref transaction — that IS the protection-verdict path. Bare `update_ref` (`cli.rs:3449–3463`) is a direct non-CAS `update-ref` write: bypasses hooks and can silently clobber a concurrent push. Components.md pins the right boundary but the trait surface exposes the unsafe primitive — pin the method.

8. [suggestion] **Heavy server-side ops are request-scoped with no bounds.** `vcs.git_import` walks full Git history inside one RPC call (timeouts on real repos — job-ify or pin limits); diff3 merge is CPU-bound on the async executor (pin offload + input caps); every export pays a temp `git clone` of the bare repo (`cli.rs:3428` — O(repo) disk+time per call); `vcs.file_get` bytes through JSON-RPC needs an inline-size cap or redirect to the objects route, else RPC becomes the bulk channel.

9. [nit] **Observability is correctly deferred, name the seams.** NFR8 already pins tracing events + typed `AppError`; `TraceLayer` wraps all routes (`app.rs:405`) and jobs log stats via `tracing::info` (`jobs/schedule.rs` pattern). No metrics infra exists to conform to — parity, not a gap. Have components.md name the GC stats log (`LfsGcStats` precedent) and commit-path span fields so codegen doesn't drop them.

10. [nit] **Object PUT route needs an explicit `DefaultBodyLimit` at mount.** Axum's default is 2 MiB — without a layer, larger blobs 413 before the quota check. LFS precedent sets 2 GiB (`app.rs:389`). Add to the Integration-seams list next to the `AppState` slot.

11. [nit] **Two small ops notes.** `RepoSurfaceFlag` check per call adds a SELECT on the want-fetch GET hot path (many small GETs per checkout) — fine single-node, worth one line on caching/joining. The client-side cache bound + dir (AC6.2.2 "configurable") need knob names if they ship as `OXIDEAN_VCS_*`.

## Positions

- **ADR-003 in-app `/api/` mount, no aux listener** — survives: PAT/proc_classes/CORS/wire-version/TraceLayer are already centralized (`app.rs:268–407`); `AppState` Arc-slot + `spawn_background_jobs` give ready extension points (`app.rs:62`, `jobs/schedule.rs:52`). A second listener duplicates auth plumbing for zero benefit under C1 (one deployable).
- **ADR-004 FS-CAS bytes + DB metadata** — survives: the proven substrate (temp→rename PUT `lfs/store.rs:34–92`, link-table GC, `vcs.quota_exceeded` write-time enforcement). Keep streaming bodies and hash-on-write.
- **ADR-005 incremental index inside the create tx** — survives: reads never see a "not yet indexed" window; my findings are pin-level (upsert semantics, refcount edge), not structural.
- **RefRegistry CAS-only, never on the commit path** — survives: append-only writes + CAS'd refs is the concurrency keystone the scale story rests on (AC2.3.1/AC5.1.x).
- **Fail-closed posture** — `vcs.disabled` single never-enabled/disabled path, `SessionOnly` unlisted default (`proc_classes.rs:127,367`), `Database::skipped()`→`db.not_configured`, cookies never authorize `/api/vcs/*` — survives as the ops kill-switch and authz floor.
- **ADR-006 `ProtectionChecker` port + host-injected `GitBackend`** — survives: "export ≡ push verdict" is structural here and keeps dependency direction host→crate.
- **Deliberate absence of a new AppState limiter** — survives: `FailedAuthLimiter` + `DefaultBodyLimit` + quota bound the surface; a new per-process limiter would diverge from the single-node precedent (`auth/login_rate.rs:6`).
- **VcsPersistence as sole SQL site + repo-row cascade** — survives: dialect parity ×3 is the heaviest ops cost and the façade is the only tested enforcement point.
