### Corrections and additions for `## Code Style`

1. **Error handling — three idioms, not one.** (a) Internal library enums use `thiserror` (`GitError` `oxidean-git/backend.rs:118`, `AuthError` `auth/session.rs:46`, `PasswordError`). (b) The `oxidean-db::Database` façade deliberately returns `Result<T, String>` — no thiserror dep; errors are matched by literal equality (`e == "database not configured"`) and substring (`UNIQUE`/`Duplicate`) in `db_err` adapters (`auth/local.rs:119-131`). (c) API handlers return `Result<T, AppError>`; `AppError{code,message,data}` + untagged `RpcResponse {ok,data}|{ok:false,error}` is the wire contract (`oxidean-core/lib.rs:103-224`). Codes are stable `domain.reason` snake-dotted (`auth.unauthenticated`, `rpc.bad_input`, `db.not_configured`) and consumed by UI branching (`session-queries.ts:27`) — never rename casually. Internals never leak: `tracing::error!` the detail, return a generic message (`auth.internal` → "authentication failed"). **No anyhow/eyre anywhere in the workspace** — binaries fail fast with `eprintln!` + `std::process::exit(1)` (`main.rs`). `unwrap`/`expect` outside tests is a soft rule (2 uses in `main.rs:10,127`).

2. **Layering — state the real model.** Flow: `oxidean-web` edge tier (serve `apps/web/dist`, meta injection, route gating, API proxy) → `oxidean-api` `app.rs` Router/`AppState` → `rpc.rs` `RpcCtx` + one `match` `dispatch` (per-arm `serde_json::from_value` input parse → `rpc.bad_input`) → domain modules (`auth/`, `repo/`, `pull/`, `org/`, `pat/`, `packages/`, …) returning `Result<T,AppError>` → `oxidean_db::Database` façade + `oxidean_git::GitBackend`; `oxidean-core` = types only, no I/O (CODE_PRACTICES boundary table); `oxidean-cli`/`oxidean-runner`/`oxidean-web` are separate binaries. There is no `services/` layer — services are per-domain internals + named structs on `AppState`/`RpcCtx` (`SessionService`, `PendingAuthStore`, `TwoFactorStore`, `*Limiter`). REST `/api/v1` is a pure translation façade over the same `dispatch` — `rest/spec.rs` `RouteDef` is the single source for router + OpenAPI; `status_for_error` maps codes→HTTP. Protocol surfaces (smart HTTP, LFS, SSH, OCI/npm/generic, OAuth, MCP, actions) are sibling route stacks sharing ACL/audit.

3. **Module/file organization.** Domain dirs use `mod.rs` façades: private `mod` declarations + `pub use` aliased re-exports (`pub use files::{create as file_create}` in `repo/mod.rs:49-52`); `pub(crate)` for cross-module internals. `lib.rs` = flat `pub mod` list + selective `pub use`; binaries in `src/bin/`; core = one `*_types.rs` per domain with glob re-export. Naming taxonomy: `*Row` db rows; `*Request`/`*Response`/`*Public` wire DTOs; `*Service`/`*Store`/`*Limiter` api internals; db verbs `insert_/find_*_by_*/list_/update_/count_/delete_/consume_/revoke_`; `#[allow(clippy::too_many_arguments)]` accepted on wide inserts; `// --- domain ---` banners section the large `Database` façade. Smell not to repeat: `email/` vs `emails/` near-collision (sender service vs `email.*` RPC domain).

4. **RPC conventions.** Procedures are `domain.verb` dotted strings — **with mixed casing and no documented rule**: `auth.two_factor.totp_begin`/`admin.auth.get_settings`/`user.get_profile` snake vs `user.getPublicProfile`/`user.listStarred`/`admin.mcp.getSettings`/`admin.workflowTemplates.create`/`repo.deployKey.list` camel. New procedure checklist: add `PROCEDURES` entry (rpc.rs:150 — the `procedures_list_matches_dispatch` test at :1851 scans match arms and fails on drift), a dispatch arm, `oxidean-core` `*Request`/`*Response` types, handler returning `Result<T,AppError>`, then `make rpc-gen` and commit the regenerated client in the same change. Requests carry `Oxidean-RPC-Version` (SemVer compat; `"1"` is a 0.x legacy alias). `system.manifest` advertises procedures + capabilities.

5. **Idioms worth naming as practices.** Trait+adapter seams for swappable subsystems — `Arc<dyn GitBackend>` + `CliGitBackend`, `Arc<dyn EmailSender>` behind `RwLock` for runtime rebuild; this is the established shape the new VCS engine should follow. Self-checking drift gates wherever two artifacts must agree: `include_str!` source-scan tests, `rpc-sync-check`, `openapi-sync-check`, `check-route-sync`, `skill-sync-check`, `check-workflow-templates`, `cli-parity-check`, `check-makefile.sh` — new duplicated/generated surfaces come with their own sync check. Migrations are authored ×3 (`migrations/{postgres,mysql,sqlite}/NNNN_name.sql`, filename-parity tested; take the next free number — gaps exist).

6. **TypeScript/web.** Kebab-case files, PascalCase components, `@/` alias over deep relatives, `import type` for type-only imports. `src/lib/*-queries.ts` = TanStack `queryOptions` factories + `queryKey` tuple consts (`["auth","me"] as const`); the generated client's result is a discriminated `{ok:true,data}|{ok:false,error}` — callers branch on `res.ok`/`res.error.code`, throw `new Error(`${code}: ${message}`)` for unexpected errors, `retry:false` + explicit `staleTime`. `useState`/zustand (`useRepoStore`) for local UI state only — TanStack Query owns server/session data. Tests colocate as `*.unit.test.ts`, `*.integration.test.ts(x)`, `*.browser.test.tsx` (plus thematic variants like `*.gate.test.ts`).

7. **Way of working.** Make is the façade for every dev-facing task (`.PHONY` + runnable recipe enforced); regenerating artifacts is part of the change, not follow-up; in-repo skills under `.agents/skills/` (octane, rust-async-patterns, rust-best-practices, tdd, semver-conventions, …) are the team's documented how-we-work and are mandatory reading before inventing workflows; `tmp/` is gitignored scratch.

### Suggested `## Code Style` wording for team-practices.md

> - **Rust**: edition 2021, rustfmt defaults, `clippy -D warnings` + `-D dead_code` + `cargo machete` + `rustdoc -D warnings` gates. Three error idioms by layer: `thiserror` enums inside libraries, `Result<T,String>` across the `oxidean-db` façade (matched literally — don't reword error text), `Result<T,AppError>` at handlers with stable `domain.reason` codes; no anyhow/eyre — binaries fail fast (`eprintln!` + `exit(1)`). Log internals with `tracing`, return generic messages.
> - **Layers**: `oxidean-web` edge → `oxidean-api` (Router/`AppState` → `RpcCtx`/dispatch → domain modules) → `oxidean-db` façade + `oxidean-git` backend; `oxidean-core` is types only. New subsystems get a trait+adapter seam (the `GitBackend`/`CliGitBackend` precedent), not inline code in `oxidean-api`.
> - **Modules**: `mod.rs` façades with aliased `pub use`; `*Row`/`*Request`/`*Response`/`*Public`/`*Service`/`*Store`/`*Limiter` suffix taxonomy; `src/bin/` for tools.
> - **RPC**: new procedures are `domain.snake_case` names (freeze existing camelCase names — wire-stable); register in `PROCEDURES` + dispatch arm + core types + `make rpc-gen` in the same change; `AppError` codes are contract.
> - **Web**: `.tsrx` islands under `components/<domain>/`, `*-queries.ts` Query modules, `res.ok`/`res.error.code` branching, colocated `*.unit/.integration/.browser.test.*`; zustand/`useState` for local state only.
> - **Drift**: any duplicated or generated surface ships with its sync check (rpc/openapi/route/skill/template + `include_str!` scan tests).
> - **Comments**: explain *why*; cite decision IDs registered in `docs/ARCHITECTURE.md`; new crate registers a `versioning.toml` component/scope.
