# Rules — u4-vcs-changeset-core

## Identity + create

- **BR4.1 (deterministic id)** — `id = "cs_" + ULID_UPPER(sha256(canonical_input)[0:16])` per the byte-exact recipe in Q1 (compact serde_json, fixed key order, omitted-None fields, mode as i64 octal, blob bare-hex, deduped-ordered parents, `{"v":1,"repo",…,"manifest_hash"}` shape, repo included as recorded deviation). `idem_key` = full sha256 hex. One `canonical_changeset()` function is the ONLY implementation (U5/U6/U7 call it).
- **BR4.2 (idempotent+concurrent create)** — identical canonical input → identical id + idem_key → `ON CONFLICT DO NOTHING` + `reselect_existing_changeset` inside `create_tx` returns the same id, one row. Concurrent identical creates serialize on the PK — one writer, both callers get the id. Concurrent divergent creates on the same parent get distinct ids by content (AC2.3.1).
- **BR4.3 (create is ref-free)** — `create` never reads or writes `vcs_refs`; `parents:[]` is a legal root. Missing parent ⇒ in-tx check fails ⇒ `vcs.not_found:parent` sentinel ⇒ `ParentNotFound` (AC2.1.5).
- **BR4.4 (file-change validation)** — per entry: `path` 1..=512 chars, POSIX `/`, no `\0`, no control bytes (<0x20, 0x7f), no leading/trailing `/`, no `.`/`..` segments, no `//`; `old_path` iff `rename` (same rules); `blob_hash` required unless `delete`, forbidden on `delete`; `mode` in the pinned set {33188(0o100644), 33261(0o100755), 41471(0o120000 symlink), 16384(0o040000 dir marker if used)} — executable bits, symlink targets-as-blobs, and renames round-trip (AC2.6.x). `author` ≤255 chars, `Name <email>` composition per Q2; `message` ≤65535 bytes; `parents` ≤64 entries (MySQL `TEXT` columns silently truncate over-limit values under `INSERT IGNORE` — bounds enforced caller-side). `committed_at` normalized `%Y-%m-%dT%H:%M:%SZ`, range-pinned to DATETIME (1000-01-01..9999-12-31); fractions rejected; malformed → `InvalidInput`.
- **BR4.5 (canonical author)** — stored + hashed verbatim after `{name} <{email}>` composition; name/email free of `<>`, newlines, control bytes.
- **BR4.6 (object-link completeness)** — `object_links` passed to `create_tx` = EVERY manifest `blob_hash` (deduped); delete entries contribute none. This is the u4 half of BR3.11 (every live blob has a link row → GC never reaps referenced objects).
- **BR4.7 (atomic write boundary)** — changeset row + file changes + object links + `path_touch` upserts land in ONE `vcs_create_changeset_tx` call; a mid-tx fault leaves nothing readable; already-PUT objects are GC-owned, unaffected.

## Refs

- **BR4.8 (strict CAS)** — update applies iff stored `changeset_id` == `expected_old` (`None` = expected-absent/create-only). `Applied(row)` → `Ref`; `Conflict{actual}` → `RefConflict` (actual=null ⟺ absent). No fast-forward or reachability enforcement — caller discipline.
- **BR4.9 (ref name grammar)** — `^[A-Za-z0-9][A-Za-z0-9._/-]{0,254}$` and reject `..`, `//`, leading/trailing `/` or `.`, `@{`, `HEAD`, `refs/`-prefix → `InvalidInput` before any DB call. Names matching an id shape (`is_changeset_id` body or pure 40/64-hex) are also rejected — creatable-but-unresolvable refs (id-precedence shadows them in `log from`; git forbids all-hex names for the same reason).
- **BR4.10 (CAS outcome mapping)** — `Conflict{actual:None}` + (`new=None` or `expected_old=Some`) → `RefNotFound` (absent delete/move — atomic, no pre-read). `Conflict{actual:None}` + `expected_old=None,new=None` → `Ok(Ref{name,changeset_id:None})` (assert-absent noop). Retried landed CAS → `RefConflict` by design (non-idempotent).
- **BR4.11 (no implicit refs)** — fresh repo lists `[]`; nothing creates `main`; no ref op merges divergent heads (u5 merge changesets reconcile).

## ReadIndex

- **BR4.12 (eager kinds)** — `path_touch` upserts ride inside `create_tx` (one row per file change + one `old_path`-keyed row per rename; key `{sha256(path)[0:32]}\x01{committed_at}\x01{cs}`). Keys unique per (path,cs) → same-parent siblings never collide under LWW.
- **BR4.13 (lazy materialization)** — `tree(cs)` folds `tree(parent[0]) + delta(cs)` along the first-parent chain (merge manifests are relative to first parent — AC2.4.1) until a `tree_snap` ancestor or root; entries written chunked, `tree_snap` in a separate FINAL call. `file_at(cs,path)` = same fold for one path (delta touch → blob/mode or delete-not-found; snap ancestor → entry; root → `PathNotFound`).
- **BR4.14 (graph answers)** — `log` = `(committed_at,id)` max-heap frontier + `{"n"}` skip-replay cursor (Q4); `merge_base` = canonical-orientation paint-down (always mark `lo`'s ancestors, BFS levels from `hi` — call-order-independent, matching the `{lo}\x01{hi}` sorted cache key), mark cap 250k → `FrontierTooLarge`, both inputs existence-checked; the pick is "a minimal-BFS-distance common ancestor" — deterministic and contract-adequate, may be a dominated ancestor (documented, not claimed as the full base set); `path_history` = `path_touch` keyset scan (order = chronological in key); `blame` = ancestry-ordered touches + successive blob diffs, sharded cache `{cs}\x01{hash32}\x01{chunk}`.
- **BR4.15 (read discipline)** — `limit` clamp `1..=500` (facade-side); malformed ids/cursors → `InvalidInput`/`CursorMalformed` → `vcs.invalid_input`; well-formed absent targets → `NotFound`/`PathNotFound`/`BaseNotFound` — NEVER ambiguous empty success: every read entry existence-checks its changeset inputs (`vcs_get_changeset`) before walking.
- **BR4.16 (boundaries)** — `server` feature only; facade calls only (zero new facade methods, zero SQL in-crate); `DbNotConfigured` on `is_skipped()`; `ObjectStore` read-only edge for blame/diff bytes.
- **BR4.17 (bytes boundary, amended)** — create/write path takes `blob_hash` only (object bytes already PUT via u3). Read paths (blame, diff patches/totals) MAY open blobs via `ObjectStore::get`; `text_diff` is the shared line-diff module u5 reuses.
- **BR4.18 (sentinel-exact decode)** — four literals only (Q7); everything else `Internal`.
- **BR4.19 (schema delta claim)** — u4 claims a `0054` migration shipped in **all three** dialect dirs (the `migration_parity` test + FR15.5 enforce filename parity): real ALTERs in mysql/ (`vcs_derived_index.index_key VARCHAR(255)→VARCHAR(560) COLLATE utf8mb4_bin`, `vcs_refs.name` and `vcs_file_changes.path` `COLLATE utf8mb4_bin` — case-variant paths/refs must not PK-collide under `*_ci`), no-op comment-only files in postgres/ (bytewise equality) and sqlite/ (BINARY default). Recorded as a sanctioned U2-delta under this unit's source manifest.
