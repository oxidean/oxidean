### Blockers (things that would break code-generation if built as written)

1. **BR1.3/Q4's "admin" tier has no target variant.** `PatProc` (crates/oxidean-core/src/proc_classes.rs:16-125) has no `Admin` variant — the repo-flag-toggle precedent is `RepoAdminWrite`: `repo.issues.setEnabled | repo.pulls.setEnabled | repo.actions.setEnabled | repo.lfs.setEnabled | repo.templates.setEnabled` all classify `RepoAdminWrite` (proc_classes.rs:300-315). `vcs.repo_enable` is the same shape. Pin `RepoAdminWrite` explicitly — it works end-to-end with zero new machinery (classic `repo` via `classic_scopes_for` proc_classes.rs:402-404, FG `administration:write` via `fg_repo_perm` bearer.rs:610, correctly absent from `public_repo_covers` proc_classes.rs:377-390, covered by `FIRST_PARTY_SCOPES` scope_catalog.rs:416-419 so `cli_mcp_procs_covered_by_first_party_scopes` commands.rs:4009-4026 stays green). Inventing a new `PatProc` variant ripples through four mapping fns; leaving "admin" vague invites either that or `SessionOnly` (which would make `ox vcs enable` non-token-callable and break the coverage test once u8 registers the proc).

2. **BR1.2 contradicts BR1.3 on proc_classes membership.** BR1.2 logic: "IF a name is not in the pinned 17 THEN it must not appear in PROCEDURES or proc_classes." BR1.3 + C2 (`proc-classes-alias`) + Q4 put two route-alias names in `classify_pat_proc` while keeping them out of `PROCEDURES`. Both cannot hold as written — an implementer following BR1.2 omits the aliases and object-route PAT authz fails closed to `SessionOnly` for every token. Fix BR1.2 to exempt the pinned aliases and name them (`vcs.object_get`/`vcs.object_put` per contract-design review R-17). Note the existing `authorize_pat_on_repo` convention maps routes onto *existing* procedure names (`"release.update"` at release_assets.rs:198-204, fn at bearer.rs:735) — synthetic alias strings work mechanically (`classify` takes `&str`, bearer.rs:441-442) but are a new pattern worth naming.

3. **BR1.5's null-vs-absent distinction is not implementable with `Option<T>`.** serde auto-defaults `Option` fields: absent→`None`, explicit `null`→`None` — indistinguishable. `Option<Option<T>>` + `#[serde(default)]` collapses identically (serde_json `null` → `visit_none` → outer `None`); the existing `icon_name: Option<Option<String>>` at action_types.rs:491 does not actually distinguish either (no `serde_with` dep — oxidean-core/Cargo.toml is serde/serde_json/schemars only). Concretely dangerous for `vcs.ref_update`: `new` omitted → `None` → delete semantics, a silent ref-delete on a malformed call. The DTO needs a presence-enforcing encoding — a `Nullable<T>` newtype (non-Option field with custom `Deserialize` so absent → `missing_field` error) or `serde_json::Value` fields — and BR1.5 should name the mechanism, not just the intent.

4. **WF2.5's parity claim is vacuous.** `make rpc-gen` runs `cargo run -q -p oxidean-api --bin rpc-gen` (Makefile:95-96), whose `index.ts` is one hand-maintained string literal (rpc_gen.rs:11-6020, `createClient` at :3745) — nothing derives TS from the Rust DTOs or `PROCEDURES` (only `languages.ts`/`scope-catalog.ts` are data-driven, :6038-6160). `rpc-sync-check` = regen + `git diff --exit-code -- packages/api-client` (scripts/check-rpc-sync.sh:6-7) — it verifies the committed file matches the template, never that the client covers the 17 procedures. Forget the template edit and `rpc-sync-check` still passes green. BR1.8's "regenerated @oxidean/api-client member" surface needs an explicit check (e.g., a test asserting `PROCEDURES` names appear in the generated index.ts) or the claim should be softened. Also note `rpc_gen.rs` lives in oxidean-api — the template edit crosses into u7's crate.

### Suggestions (improvements, cheap to fold now)

- **Name the real denial codes in WF1.** Step 2's "`rpc.bad_input`/`vcs.not_found`-class" is wrong on both paths: unknown names hit `rpc.unknown_procedure` (rpc.rs:1837-1840); for token callers the `SessionOnly` class denial fires *before* dispatch as `auth.pat_scope` (rpc.rs:509 → bearer.rs:445-447).
