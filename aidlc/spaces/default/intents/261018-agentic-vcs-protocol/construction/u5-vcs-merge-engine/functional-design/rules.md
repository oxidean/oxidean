# Rules — u5-vcs-merge-engine

BR5.x — binding rules for MergeEngine. Wire/persistence invariants live in u1/u2/u4; these govern the merge/rebase computation itself.

- **BR5.1 (first-parent orientation).** `merge(a,b)` writes `parents=[a,b]` and `changes = manifest_diff(tree(a), merged)`; wire `a` is the ours/into side. The changed-file list is ALWAYS relative to the first parent (FR2.4, AC2.4.1).
- **BR5.2 (fast-path truthfulness).** `is_ancestor(a,b)` ⇒ `FastForward{b}`; `is_ancestor(b,a)` ⇒ `FastForward{a}`; `a==b` subsumed. No changeset written; `fast_forward: true` reported. The ancestor test is the engine's OWN bounded BFS over `vcs_changeset_parents` — `ReadIndex::merge_base`'s pick may be dominated (SR4.11) and is NOT trusted for ancestry decisions.
- **BR5.3 (no silent partial merge — TWO-PASS classify).** `ObjectStore::put` repo-links unconditionally (`vcs_object_links`; GC never reaps linked objects — devsecops 1), so **no `put` may run before the conflict-free checkpoint**. Pass 1 classifies every path and runs `merge3` for diverged blobs, recording the locally-computed `sha256` id per merged path — bytes discarded, zero `put`s. Any conflict/abort ⇒ zero changeset/file_changes/index rows AND zero object rows/links (nothing reached the store). `manifest_diff` + its cap check AND the deterministic create-input pre-check (message bytes, author chars — mirrored `compose_author`) also run pre-checkpoint so NO deterministic abort can fire post-`put`. Pass 2 (conflict-free, inputs pre-validated) re-runs `merge3` per merged path — deterministic, identical bytes → identical id — and `put`s; then `create` (FR7.4). The only remaining post-`put` aborts are infra-level (put quota/Io, tx failure, raced sentinel decodes) — named residual. Same ordering on the rebase path (WF5). (Derived-index rows lazily written inside `tree`/`merge_base` reads are u4-owned mechanics, not merge writes.)
- **BR5.4 (deterministic merge table).** Classification is a pure function of `(mode, blob_hash)` triples + the bounded side-manifest maps; conflict list sorts by path byte order. Same inputs ⇒ same merged tree ⇒ same id.
- **BR5.5 (text test — u5-new, not shared).** diff3-eligible ⟺ no `0x00` in the first 8 KiB, checked ONLY AFTER the size pre-step. `text_diff` is binary-safe — no shared predicate exists or is claimed; "mergeable" ≠ "diffable" is deliberate.
- **BR5.6 (never diff3 non-regular modes).** `mode ∈ {0o120000, 0o040000}` entries merge only via pick rules; both-diverged ⇒ `type` conflict.
- **BR5.7 (one entry per path).** Conflict precedence inside the per-path table: `type` > `mode` > `binary`/`content`; `delete` stands alone; `rename` is detected by the separate cross-path provenance pass (one entry on the ours-side target). Rename-collided targets `{prov_o[old], prov_t[old]}` are marked **claimed** — the classify skips them, so a path never emits two entries (reviewer 3 suppression). rename-vs-delete (`old` renamed by one side, deleted by the other) emits one `rename` conflict on the renaming side's target — never a silent keep (reviewer minor 1); rename-vs-modify keeps its `delete` kind on `old` but `detail` names the rename target.
- **BR5.8 (conflict envelope).** `MergeError::Conflict` = `Vec<VcsConflictEntry>` path-sorted, `detail ≤ 200` chars, no content echo; collection stops at `merge_conflict_max + 1`; the wire constructor truncates at 500 + `truncated:true`.
- **BR5.9 (caps typed, never silent).** `merge_paths_max` (10_000) bounds EACH accumulated tree AND the emitted manifest (`changes.len()` checked before `create` — the wire's 10k bound is RPC-side only, the engine enforces it); `merge_blob_max`, `ancestor_probe_max` (is_ancestor + mark phase — ancestry-closure scale), `side_walk_max` = 25_000 (side-exclusive delta only — NEVER the mark phase; deliberate tightening vs u4's 250k for a synchronous per-node-manifest walk, reviewer nit 3), `rename_probe_max`, `LINE_CAP` all ⇒ `vcs.too_large`/`TooLarge` — never truncation or approximation.
- **BR5.10 (spawn_blocking boundary).** Only `merge3` runs inside `tokio::task::spawn_blocking` on owned `Vec<u8>`s; blob reads + tree materialization stay async. JoinError ⇒ `Internal`.
- **BR5.11 (idempotency via content).** Outcomes are pure functions of inputs; resubmission returns the same `changeset_id` via u4's `idem_key` — no engine-side dedup.
- **BR5.12 (no ref motion).** The engine never reads or writes `vcs_refs` (G5); ref advance is the caller's separate CAS.
- **BR5.13 (rebase = first-parent replay).** Replay basis `parents[0]` (∅ for a root — synthesized empty `BTreeMap`, never a `tree()` call); extra parents of merge nodes dropped — rebase produces linear history.
- **BR5.14 (rebase guards).** `new_parent == old_base` ⇒ `FastForward{cs}` honest no-op — applies to ≥2-parent nodes too ("already there", not "collapse"). `is_ancestor(cs,new_parent)` (incl. equality) ⇒ `InvalidInput` — descendant/cycle typed. `new_parent` ancestor-of `cs` ⇒ legal roll-back. Disjoint target ⇒ LEGAL (replay needs only `old_base`).
- **BR5.15 (rebase message).** `None` ⇒ source message verbatim; merge `None` ⇒ `merge {b} into {a}` — deterministic so ids stay content-derived.
- **BR5.16 (author threading — dual validation).** `author_*` are params; validated TWICE — a mirrored deterministic pre-check at entry/WF1.9 (caller-input errors can't fire post-`put` — the earlier "validated once, no re-check" is STRUCK, reviewer-3 F3) and authoritatively inside `create`.
- **BR5.17 (rename provenance bound + semantics).** Provenance maps come from `side_manifest_pair` (merge) or `vcs_list_file_changes(cs)` (rebase — the SOURCE's own manifest, never a target-side walk): mark ≤ `ancestor_probe_max`, side-exclusive nodes ≤ `side_walk_max`, rename rows ≤ `rename_probe_max` — over ⇒ `TooLarge`, never silent rename-blindness. `compose_provenance`: chains compose transitively to the tip-visible target; cycles and multi-writer `old` keys are dropped (ambiguous ⇒ no provenance); a rename whose final target is absent from the side's tip tree provides none.
- **BR5.18 (error shape).** `MergeError` variants `NotFound | InvalidInput(String) | NoCommonAncestor | TooLarge | QuotaExceeded(QuotaScope) | Conflict(Vec<VcsConflictEntry>) | DbNotConfigured | Internal(String)`; messages never echo rejected values — `ChangesetId::parse`'s error text (which embeds the raw id) is DISCARDED, a fixed `field: reason` message constructed (devsecops 8). `Display for Conflict` renders `"conflict: {n} paths"` — count only, never entry paths (devsecops 3 — `warned()` logs `%e`, so a listing impl would leak paths to logs). Every typed return passes `warned()`. `MergeError` does NOT derive `PartialEq` (`VcsConflictEntry` lacks it — recorded deviation from u4's convention; tests field-compare).
- **BR5.19 (no new facade surface; no u4 file edits).** Everything rides existing `vcs_*` facade methods + u4 index/store APIs + u3 object APIs. `read_index.rs`/`changeset_store.rs`/`text_diff.rs` are u4-fingerprint-bound — this unit adds `merge_engine.rs` only; shared helpers are imported crate-internally (`split_lines`, `diff_lines`), not moved.
- **BR5.20 (rebase root edge).** A root changeset rebases with `old_base = ∅` — legal and deterministic. (Merge-side ∅ is unreachable: disjoint histories fail `NoCommonAncestor` at WF1.2 — the earlier ∅-merge claim was struck, devsecops 2.)
- **BR5.21 (size pre-step before text test).** Blob fetch = `take(merge_blob_max + 1)` → over ⇒ `TooLarge`; ONLY THEN the 8 KiB NUL test. An over-cap blob is a limit error, not a `binary` conflict.
- **BR5.22 (LINE_CAP degeneration + count-first).** `merge3` returns `Result<Vec<u8>, Merge3Fail>` where `Merge3Fail = TooLarge | Regions(Vec<ConflictRegion>)` — the cap error must be representable (devsecops 7). Inside the spawn_blocking closure, a `memchr`-count of `b'\n'` runs BEFORE `split_lines` (devsecops 10 — a 4MiB newline-dense blob would otherwise allocate ~4M line vecs / ~100MB before tripping). Combined line counts > `LINE_CAP` ⇒ `TooLarge` BEFORE `diff_lines` — its whole-range-hunk fallback must never be reached from merge.
- **BR5.23 (manifest mapper).** `manifest_diff`: absent-in-first-parent ⇒ `add` — OR provable `rename` iff `prov[old]==p` AND `old ∉ merged` AND **`old ∈ first_tree`** AND `(mode,blob)` equality vs the provenance side's tree (reviewer 7 — old must exist at the first parent); absent-in-merged ⇒ `delete{mode: first_parent_entry.mode}` (LEGAL_MODES required even on deletes); diverged ⇒ `modify`. Unprovable ⇒ delete+add. `changes.len() > merge_paths_max` ⇒ `TooLarge` pre-`create`. Multiple qualifying `old`s on one target `p` ⇒ byte-first `old` wins (BTreeMap order — deterministic). The `delete` arm SKIPS any `old` already claimed by an emitted `rename` row (devsecops 5 — else every emitted rename carries a phantom `delete{old}` that falsifies `path_touch`/`blame` history).
- **BR5.24 (mode divergence is conservative-by-design).** chmod-vs-edit ⇒ `mode` conflict (no auto-pick — recorded decision, devsecops 11; a silent mode pick can't be wrong and can't be undone by the caller).
- **BR5.25 (error bridge completeness).** Every consumed error type maps per Q8 — `QuotaExceeded` keeps its own variant → `vcs.quota_exceeded` (never folded into `TooLarge`); `ObjectStoreError::{NotFound,InvalidHash,Stream,DbNotConfigured}` ⇒ `Internal` defensive; `IndexError::CursorMalformed` ⇒ `Internal` inside `full_tree` (engine-minted cursor = corruption, not input); `IndexError::DbNotConfigured` ⇒ `DbNotConfigured` (dedicated variant — u4 convention); `io::Error` from blob reads ⇒ `Internal` (devsecops 9 — fourth error channel).
- **BR5.26 (paged tree accumulation).** `tree()` pages at `SCAN_PAGE=500`; the engine cursor-loops whole trees into `BTreeMap`s and enforces `merge_paths_max` DURING accumulation — over-cap aborts mid-walk, not after materialization.
