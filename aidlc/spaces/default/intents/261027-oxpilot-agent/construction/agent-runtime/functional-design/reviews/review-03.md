## Review

All five open iteration-2 items were re-verified against the current artifacts and the shipped code. R-19's `turn_cancel` row now carries C1's pinned `{aborted: bool}` payload and `no_active_turn` error (conformance checked against contract-summary.md:43-45). R-20's airtight seam is real: BR3.4/WF5 put `message_queue`'s {re-verify-live + `enqueue` commit} under `turns().admission_lock(session_id)` and BR4.1/WF3.6 put the dying turn's {release + recheck-drain} under the same per-session lock — the two critical sections serialize, so a row either commits before the locked recheck (the drain sees it, chains) or verifies after release and refuses `session_active_turn_absent` onto the POST path. Both halves of each section are genuinely required: re-verify outside the lock reopens the hole (commit lands post-recheck), commit outside reopens it the other way (verify passes pre-release, insert lands post-recheck). Lock-order audit found no cycle — admission_lock → `ActiveTurns.map` is the only acquisition order, and `claim`/`get`/`release` never hold `map` while taking the admission lock. The two-maps-across-rebuilds concern resolves in code: every slot rebuild carries `prior.turns` (settings.rs:448/490/538/546/646/660; `turns()` clones the slot Arc, oxpilot.rs:711-714), so a registry living on `ActiveTurns` is one map per session for process life. R-15 is complete: `ARGS_SUMMARY_MAX` (2 KiB, truncate-with-marker) is pinned on `ToolCall.args_json`→`args_summary` for frame + card (entities.md:91) and the `emitted_deltas` unbounded-by-design accepted-risk note is recorded (entities.md:22, bounded implicitly by `TURN_MAX_DURATION` × throughput). R-22 pins the per-round delta slice (functional-spec.md:87-89). All four R-23 sub-pins landed: claim-loss exits quietly with the corrected covering description (BR4.1, WF3.7), `pending_content := ""` fits the non-nullable `String` (routes.rs:459) and can never equal a validated non-empty resend, BR5.2 enumerates the minted codes, and the recheck-drain `Err` arm is pinned (BR4.1, WF3.6).

R-21 is only partial: WF2.4b's mint→persist→frame→invoke→`ChatMsg` sequence implies the effective id flows everywhere, but BR3.1's invoke line still reads `call_id:id` — the raw stream id — and entities.md's `ToolCall.call_id` constraint still says "the provider's call id"; the two normative statements contradict the resolved-id flow the review required.

New defects are all Minor and concentrate on the two additions this iteration introduced: the `admission_lock` mechanics (registry lifetime, mutex flavor across DB I/O, panic mid-section) are unpinned; the `turn_cancel` row still deviates residually from C1 (`forbidden`→`not_found` swap unflagged, and the `{aborted: bool}` semantics for the already-terminal-but-unreleased window unpinned); whether an aborted turn still drains+chains the queue is unpinned (moot under C8's cascade, user-visible under `turn_cancel`); and BR5.2's minted-code list misses the `oxpilot.disabled` terminal code WF2.1 emits.
