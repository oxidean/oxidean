- **Intent-relevant finding**: Every seam `/oxpilot` needs already has a working precedent in-repo. (1) Route+auth gate: add an entry to `SHELLS` (`crates/oxidean-web/src/shells.rs:48`, `protected:true`, pattern `[L("oxpilot")]`) plus `apps/web/src/pages/oxpilot.astro` + `apps/web/src/routes/oxpilot.tsrx` following the `/settings/ai` recipe — `AppPage`/`AppAccessGate` session-query → `usePageRedirect("/login?returnTo=/oxpilot")` (`app-page.tsrx:20-33`, `routes/settings/ai.tsrx:32`) — and a `routeCoverageManifest` row (`route-coverage.manifest.ts:191`). (2) Streaming chat: SSE through `/api/` is proven end-to-end — `stream_job_log` (`action_downloads.rs:308+`, mounted `app.rs:125`) uses a snapshot-frame→append-frame mpsc→`sse::Event` design that survives the web tier (`text/event-stream` compression exclusion, `oxidean-web/src/main.rs:122`) and the edge `/api/` prefix (`proxy.rs:17`); an `oxidean-api-oxpilot` domain crate registers `oxpilot.*` procedures per the issue-#162 pattern (`PROCEDURES` const + `dispatch` arm in `rpc.rs:52-145`, disjointness enforced by `check-api-domain-graph.mjs`). (3) Feature flag + operator provider config: copy the `OXIDEAN_MCP_ENABLED` env + `admin.mcp.getSettings/updateSettings` DB-override pattern (`mcp.rs:169-201`, `admin/settings.rs:540-561`, `oxidean-db/src/mcp_settings.rs` → new `oxpilot_settings` migration, 81st→82nd file per dialect). (4) Auth/credentials for computer use: session-cookie RPC auth is automatic; outbound connector credentials map onto the PAT fail-closed model (`proc_classes.rs:160-567`, `pat/bearer.rs:808+`) — new procs are `SessionOnly` until classified, which is the desired v1 stance; `aes-gcm` at-rest secret encryption (Actions/TOTP) is the custody precedent. (5) Audit + rate limit: `audit::record` (`api-core/src/audit.rs`, `audit_events` table) is one call per site; per-process sliding-window limiters exist (`pat/rate_limit.rs`, `user/rate_limit.rs`) to copy for turn/token caps.
