# aidlc-developer-agent — u6-vcs-git-interop functional-design review

Findings verified against code (file:line). Ordered by severity.

1. **BLOCKER — Export anchor/parent-mapping lookup direction does not exist.** WF4.2/BR6.14 walk `vcs_changeset_parents` (changeset ids) and ask "is this changeset linked, and to which git oid" — but `vcs_lookup_import_link(repo_id, git_oid) -> Option<changeset_id>` is strictly `git_oid → changeset_id` (`oxidean-db/src/vcs.rs:2550–2556`); `vcs_import_link_page` is ordered by `git_oid` (`vcs.rs:2274–2352`), so per-node probing is O(total links). The `ident-cs:` sidecar can't substitute — it's written only at import (export-backfilled links lack it) and its payload carries no git_oid. Fix: add a `vcs_lookup_import_link_by_changeset(repo_id, changeset_id) -> Option<git_oid>` facade — `idx_vcs_import_links_changeset` already exists in all three dialects (`migrations/*/0053_vcs_schema.sql`).

2. **BLOCKER — Fold-forward single `BTreeMap` produces wrong trees for any DAG containing a merge.** Merge changesets store the delta vs `parents[0]` (`manifest_diff(first, merged, …)`, `merge_engine.rs:1059–1128`, merge creates `parents:[a,b]` at `:476`), so `tree(C) = tree(C.parents[0]) + changes(C)` — NOT `tree(previous-in-topo-order) + changes(C)`. On any fork/merge topology the accumulator holds the wrong pre-state and mints commits whose trees don't match the changesets (violates AC7.2.4 silently). Fix: materialize each node's tree via `index.tree(repo_id, cs)` (u4's `materialize` does the correct first-parent fold with snapshot caching, `read_index.rs:812–915`) or keep per-node trees keyed by changeset id; if a custom fold is kept it must replicate `materialize`'s sequential remove-then-insert rename ordering (`read_index.rs:836–862`) exactly.

3. **BLOCKER — The `Denied`/`Conflict` mapping at the branch move is dead code today.** `fast_forward_ref`/`force_update_ref` call `run_git_with_env` directly (`cli.rs:3283, 3290, 3438`); every failure is `GitError::Process`. The `Process→Conflict`/`Denied` stderr remap exists only inside `commit_files` (`cli.rs:1735–1748`), and `backend.rs:755` documents "Non-FF → `GitError::Process`". A raced non-ff move → `Internal` not `RefConflict`; a hook decline → `Internal` not `Forbidden`. This is first-class, not just TOCTOU: the update hook evaluates pushed commits (`pushed_commits`, `cli.rs:111`) including signature rules that can't be pre-checked on unwritten objects, so denial at push is expected. Fix: port the stderr remap (or a shared helper) into both methods alongside the new `actor_capability` param.

4. **MAJOR — Annotated-tag tips break `heads` resolution and `from` resolution.** `list_refs` binds `%(objectname)` (`cli.rs:1906`) = the tag *object* oid for annotated tags, and `rev_parse` likewise returns tag oids; `rev-list` peels them so commits still import, but links are keyed by commit oid — `link_lookup(tag_oid)` misses → `heads[i].changeset_id` (non-optional `ChangesetId`, entities.md) can't be filled. Fix: peel every tip with `{tip}^{commit}` when snapshotting (also fixes `from=<annotated tag>` and non-commit `from` args), or add a `%(*objectname)` peeled field to `GitRef`.

5. **MAJOR — `ident-cs` sidecar cannot deliver AC7.4.1 byte-identity.** Payload `{a_tz, c_name, c_email, c_unix, c_tz}` stores nothing raw for the *author* except tz; `compose_author` trims the name and `sanitize` replaces control bytes (`changeset_store.rs:439–461`), and `GitIdent{name,email}` as `String` can't represent non-UTF8 idents at all (git permits arbitrary bytes). Any sanitized/trimmed/non-UTF8 ident re-exports different bytes → different commit oid than the original. Fix: sidecar stores raw ident bytes (base64) for author and committer — `{a_name,a_email,a_unix,a_tz,c_*}` — and `GitIdent` fields become `Vec<u8>`-tolerant.

6. **MAJOR — Non-UTF8 file paths silently corrupt.** `-z` diff/ls-tree output parsed to `String` (lossy or unspecified) collapses distinct byte paths onto `U+FFFD` → either `duplicate path` `InvalidInput` or an imported path that never existed in git; export then writes the mangled name back. Design is strict on non-UTF8 *messages* (BR6.13) but silent on paths. Fix: `NameStatusRow.path`/tree entries byte-faithful (`Vec<u8>`) → deterministic `InvalidInput` on non-UTF8, same rule as messages.

7. **MAJOR — `commit-tree` honors repo config `commit.gpgSign`.** A bare repo with `commit.gpgsign=true` makes `write_commit` attempt signing → fails (no keyring) or emits a non-deterministic signature → breaks deterministic minting. Fix: invoke `git -c commit.gpgSign=false … commit-tree`, pass all six `GIT_AUTHOR_*`/`GIT_COMMITTER_*` envs, and feed the message via stdin (`run_git_stdout_env_stdin` exists, `cli.rs:337`) — VCS messages have no NUL check (`changeset_store.rs:481` validates length only) so argv `-m` can spawn-fail on a stored NUL message.

8. **MAJOR — `diff-tree -M` rename detection inherits repo `diff.renameLimit` config.** No `-l` flag is pinned, so per-repo config can change rename resolution → different manifest → different changeset id → a false "divergent mapping" `Internal` on re-import after a config change. (`diff.orderFile` is harmless — `canonical_changeset` re-sorts; explicit `-M` already overrides `diff.renames`.) Fix: pin `-l<n>` or `-c diff.renameLimit=<n>` inside `commit_name_status`.

9. **MAJOR — `git mktree` without `-z` C-unquotes names.** VCS paths may contain `"` and `\` (`validate_path` rejects only NUL/control/`.`/`..`, `changeset_store.rs:241–266`); non-`-z` mktree input applies `unquote_c_style` → silent name corruption → wrong tree oids. Fix: `git mktree -z` with raw names and `{:06o}` mode strings (`040000`/`100644`/`100755`/`120000`); note mktree normalizes entry order itself, so the "byte-sorted input" wording is unnecessary (min git is 2.5).

10. **MAJOR — `git diff-tree --root` single-commit form prints the commit-id record first** ("the ID of the first (or only) commit, followed by a newline, is printed"); `-z` doesn't suppress it — the `NameStatusRow` parser will consume the sha as a status row on every root commit. Fix: pin `--no-commit-id` in the backend call (the argv two-tree form emits no header — no skip needed there).

11. **MAJOR — `rev_parse` never returns `NotFound`** (`cli.rs:3442–3447`): failures are `Process`, and well-formed-but-absent oids resolve successfully (rev-parse is syntactic without `^{…}`/`--verify`). `from` misses and absent `refs/heads/{branch}` → `Internal`, not `NotFound`/branch-create. Fix: use `rev-parse --verify --quiet {rev}^{commit}` + stderr sniffing — one change fixes `NotFound`, tag peel (#4), and non-commit `from` rejection.

12. **MAJOR — Claim verify-read does not bound the race.** Upsert is not CAS (`vcs.rs:1987–2079`): A upserts nonce_a → re-reads nonce_a → proceeds; B upserts nonce_b → re-reads nonce_b → proceeds. Only an interleaving between upsert and re-read rejects, so BR6.6's "one side types import_state" is not guaranteed — correctness rests wholly on idem/link convergence (which does hold: `create_tx` returns the winner's id on unique-race, `vcs.rs:994–1008`). No stronger facade primitive exists (`vcs_import_links` insert-if-absent is atomic but has no delete for release). Fix: keep the marker but document mutual exclusion as best-effort and re-verify the nonce before the final cursor write to shrink the window.

13. **MAJOR — Skip-index reorder can silently drop commits.** `rev-list --topo-order` is deterministic for fixed input+version but emits *a* valid topo order, not *the* topo order — a host git upgrade (or object GC between pages) mid-backfill can re-derive a different order; `skip` then skips unprocessed commits (parent-check `Internal` catches only skipped *parents* — skipped tips/leaves go silent). Fix: store `last_oid` in the cursor and verify `list[skip-1] == last_oid` on resume → `ImportState` on mismatch.

14. **MAJOR — `lazy_import` re-converts the whole ancestor cone** (up to 250k commits) on the read path even when only the tip is new — `import_one` runs cat_commit + diff-tree + per-path cat_blob/put for every enumerated commit. Fix: `link_lookup` early-skip per enumerated commit before `import_one` — links are written parent-first, so the first linked node's tail is all linked; still convergent and keeps `import_one` verbatim for actual conversion.

15. **MAJOR — `rev_list(repo, tips) -> Vec<String>` materializes unbounded output** — a multi-million-commit repo allocates hundreds of MB before `rev_list_max` (250k) trips. Fix: `rev_list(repo, tips, limit)` issuing `--max-count=limit+1` and reporting overflow (`^oid` exclusion is *not* expressible — the boundary would need git oids of linked ancestors, which is DB state; #14's early-skip is the correct mechanism). Also early-return `Ok(vec![])` on empty tips (bare `git rev-list` with no revs errors — currently the empty-repo case → `Internal` instead of `{imported:0, done:true}`).

16. **MAJOR — `GitError::InvalidArg → Internal` mislabels user input, and branch/`from` validation is weaker than git's refname rules.** `validate_treeish` (`cli.rs:676–691`) accepts `a//b`, `x.lock`, `a[b`, `a@{b}`, `foo.` — all invalid refnames that die later as `Process→Internal`; and `from`/`git_oid` InvalidArg is a client error typed `Internal`. Fix: interop-side validation on `from`/`branch` to `git check-ref-format` parity (new backend method) → `InvalidInput`, and `is_git_oid` shape check on `lazy_import`'s arg.

17. **MAJOR — `import_blob_max` can't be enforced pre-read; `ls_tree_entry` returns no size and `cat_blob` returns full `Vec<u8>`** (`cli.rs:1859`) — an over-cap blob is fully materialized (subprocess output + alloc) before `TooLarge` can fire. Fix: one `ls-tree -r -l -z <sha>` per commit — replaces N per-row `ls_tree_entry` subprocess calls AND yields per-blob oids+sizes for pre-read cap checks.

18. **MAJOR — Missing error bridges and cap field.** (a) `store.create` → `ChangesetError`, `index.tree` → `IndexError`, `objects.put/get` → `ObjectStoreError` → `InteropError` mappings are unspecified — each is a distinct enum needing a table (u5 precedent: `map_changeset_err`, `merge_engine.rs:135–157`; `QuotaExceeded` must carry `QuotaScope`). (b) `InteropCaps` lacks an ancestor-probe bound for WF4.4's `is_ancestor` BFS — add `export_ancestor_probe_max` (u5 uses 250_000, `merge_engine.rs:183`). (c) WF2 `lazy_import` omits the eager `is_skipped`→`DbNotConfigured` first step WF1/WF4 have. (d) `MergeEngine::{full_tree,is_ancestor}` are `async fn` private (`merge_engine.rs:585,611`) — "u5 primitive" means re-implement or promote to `pub(crate)`.

19. **MINOR — `cat_commit` parse pins absent.** `cat-file commit` output has folded continuation headers (`gpgsig`, `mergetag`, `encoding` — a space-led line continues the previous header); `author`/`committer` lines can be malformed in the wild (missing `>`/tz, non-UTF8 bytes). `message` = bytes after first blank line is right, but pin: folded-header handling, last-` <`/`>` ident split, malformed-ident → `InvalidInput` (never panic/lossy).

20. **MINOR — `NameStatusRow` `-z` rename shape.** `-z` emits `R<score>\0<src>\0<dst>\0` (two path records — parse arm must consume both) and `T` rows exist independent of `-M` (design's "T only with -M" is wrong but harmless — it's a typechange row). `R`/gitlink old-side behavior (gitlink → file rename) is unspecified — decide skip-vs-modify deterministically.

21. **MINOR — `from="main"` resolves `refs/tags/main` before `refs/heads/main`** (gitrevisions precedence) — a shadowing tag silently imports different history. Fix: peel `^{commit}` and prefer `refs/heads/{name}` when `from` is a bare short name, or document tag-wins.

22. **MINOR — miscount + shape gaps.** (a) `actor_capability` touches FOUR production call sites not three: `force_update_ref` mirror `engine.rs:536`, `fast_forward_ref` `engine.rs:863,991`, `sync_fork.rs` + tests `cli.rs:4557,4591,4670,4675`. (b) `objects.get` returns `tokio::fs::File` not bytes (`object_store/mod.rs:311`) and has no read cap — enforce `export_blob_max` during `take()` (defense; stored bytes are bounded by put's write cap). (c) `VcsDerivedIndexUpsert.covering_changeset` is required (`vcs.rs:162`) — `active`/`cursor` rows need a specified value (`""` or repo marker). (d) Cursor/tip count unbounded — a many-ref repo emits a multi-MB wire cursor; bound tips or bytes. (e) ident sidecars write before `store.create` (WF3.6→3.7) — a failed create leaves dangling rows; benign (same inputs → same id) but ordering after create is cleaner. (f) `ProtectionChecker` needs `async-trait` added to `server` deps.

23. **MINOR — deterministic-refusal inventory (consistent, but pin for u7 UX):** `>64` parents (`MAX_PARENTS`, `changeset_store.rs:42`), `>65535`-byte messages, `committed_at` year<1000/>9999 (`normalize_committed_at`, `:427`), >512-char paths, empty author name/email (`compose_author` requires both, `:441`) — all deterministically `InvalidInput` on both paths; document that histories containing them refuse import rather than degrade.

24. **NIT —** `list_refs` already returns only `refs/heads`+`refs/tags` (`cli.rs:1907–1908`), so the `refs/oxidean/*` filter is a no-op; `heads` mid-import is fine (topo order emits tips first); `RefConflict{actual:Option}` matches `CasOutcome::Conflict` shape; `ObjectStore` isn't `Clone` — `ReadIndex` needs a second instance (u7 constructs both; `ObjectStore::new` is idempotent on existing marker).

**Verdict:** Sound convergence architecture, but three implementation-blocking defects — the missing changeset→git_oid lookup (#1), the linear-only fold-forward (#2), and the dead Denied/Conflict move-error mapping (#3) — plus a cluster of determinism/fidelity leaks (config-dependent rename detection, quoting/UTF-8/ident byte-loss, unpinned plumbing flags) must be resolved before code generation.
