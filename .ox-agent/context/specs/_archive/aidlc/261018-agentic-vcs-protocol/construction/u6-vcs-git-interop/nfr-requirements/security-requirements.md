# Security Requirements — u6-vcs-git-interop

## SR6.1 — Bounded enumerations, typed overflow (BR6.8/BR6.19)

Every walk and buffer carries a named injectable cap on `InteropCaps` and overflows to `TooLarge`, never truncation or silent clamping: `rev_list` output ≤ `rev_list_max` (250_000 — a single ancestor-cone bound; multi-cone repos import per-ref), page window ≤ `import_commit_cap` (1_000, caller `limit` validated `1..=cap` ⇒ `InvalidInput`), tip count ≤ `cursor_tips_max` (512), serialized `CursorState` ≤ `cursor_payload_max_bytes` (32_768 — under mysql `payload TEXT`'s ≈64KiB/65,535-byte ceiling so a persisted cursor is always resumable), `tree_flat` leaves ≤ `import_tree_max` (10_000), blob reads `take(import_blob_max + 1)` / `take(export_blob_max + 1)`, export-set BFS ≤ `export_chain_max` (10_000), ff-gate ancestry probes ≤ `export_ancestor_probe_max` (250_000). **Subprocess stdout is bounded too** (devsecops-M2): the two unbounded-materializing plumbing methods take a `max_bytes` argument — `tree_flat(repo, sha, import_tree_max × 1024)` and `commit_name_status(repo, base, sha, import_tree_max × 2048)` (per-entry worst case ~600B; rename rows carry two ≤512B paths) — the backend reads stdout incrementally and kills the child past the bound ⇒ `TooLarge`, so attacker-pushable trees/diffs can never force unbounded allocation (`cat_commit`/`write_object` outputs are already single-object bounded by `import_blob_max`; `rev_list` is bounded by `--max-count`). `validate` at `new` pins `*_blob_max ≤ objects.max_object_bytes` so no deterministic `QuotaExceeded` fires mid-run (u5 `MergeCaps` convention).

## SR6.2 — Import claim is a best-effort mutex with a correctness backstop (BR6.6/BR6.4)

The `active` derived-index marker uses `{state,nonce,started_at}` claim → re-read nonce-verify → release, TTL `import_lock_ttl_secs` (900s) for stale-marker reclaim. It is NOT atomic (no CAS facade exists — dev 12): two concurrent imports on one repo can interleave. That is SAFE, not a violation — `insert_if_absent` link convergence + idempotent `create` make interleaving converge (BR6.4); the marker only prevents redundant subprocess work. Release is nonce-verified so a stale TTL-reclaimed marker never releases another importer's claim; release runs even on error paths.

## SR6.3 — Cursor integrity (BR6.6/BR6.7)

`CursorState` is opaque b64url JSON AND UNTRUSTED INPUT (caller-forged cursors are possible) — inbound `cursor.len() > cursor_payload_max_bytes` ⇒ `ImportState` BEFORE parse (devsecops-M1); malformed ⇒ `ImportState`, never a parse panic. Decoded state is revalidated field-by-field before use: `v == 1`, `tips.len() ≤ cursor_tips_max`, **every `tips[].git_oid` is oid-shaped and non-dash-led** (the SR6.4 argv guard extends to decoded cursor tips — a forged cursor must never inject flag strings into `rev_list` argv; devsecops-9), and **`skip > list.len() ⇒ ImportState`** pinned BEFORE any indexing — `list[skip-1]`/`list[skip..]` on an oversized `skip` would panic, not type (devsecops-M1). Resume continuity `list[skip-1] == last_oid` enforced ⇒ `ImportState` on drift (a mismatched skip would silently re-process or skip commits). `skip` advances by every CONSUMED entry including already-linked skips so `imported` counts fresh conversions only — a cursor can never over-report progress. `from`+`cursor` co-supplied ⇒ cursor authoritative (documented, prevents tip-set confusion attacks where a caller swaps `from` mid-resume). Byte-cap checked BEFORE upsert — an oversized serialized cursor is `TooLarge`, never written unresumable.

## SR6.4 — Process execution hygiene (BR6.24)

All git invocation pins fixed argv — `-c` config overrides positioned BEFORE the subcommand (a post-subcommand `-c` dies as an unknown flag); dash-led `from`/`rev`/refnames rejected caller-side as `InvalidInput` BEFORE argv construction (dash-led values parse as flags); commit messages and `mktree` input go over STDIN (argv `-m` spawn-fails on NUL bytes); `commit.gpgSign=false` forces unsigned mints regardless of repo config; six `GIT_AUTHOR_*`/`GIT_COMMITTER_*` envs carry raw `<unix> <±ZZZZ>` date form. `git check-ref-format` is the refname oracle — u1's `validate_treeish` is NOT reused (it accepts `a//b`, `x.lock`, `a@{b}` — dev 16).

## SR6.5 — No stderr or value echo on any error path (BR6.18/BR6.22)

Backend process errors classify through the ported `classify_push_error` — `Denied`/`Conflict` typed, everything else a FIXED non-leaking message. `InteropError` messages are `field: reason` only: no raw stderr (it can carry rejected values, absolute paths, blob content), no rejected-input echo (dash-led `from`, oversized values, malformed oids are refused without quoting), no auth material. `ChangesetId::parse` error text embeds the raw input — DISCARDED and replaced with a fixed message (devsecops-8 precedent; `is_git_oid` returns `bool` and emits no error text — nothing to discard there). The error bridge is TOTAL over every consumed enum — all 9 `ObjectStoreError` variants, 6 `ChangesetError`, 8 `IndexError` (`CursorMalformed` ⇒ `ImportState` — caller-supplied cursors ARE untrusted input, unlike u5's engine-minted cursors), facade `String` ⇒ opaque `Internal`. Unmapped ⇒ `Internal`, never panic.

## SR6.6 — Protection parity and provenance-safe ref motion (BR6.15/BR6.16/BR6.17 — AC7.2.2)

Export's ref move is gated exactly like a git push: the complete object chain writes first (the verdict needs the minted tip), `ProtectionChecker::check(repo, refname, old, new, actor_capability)` runs on the REAL `(old,new)` pair — NO force param; the impl derives intent `f(old,new)` identically to `check_ref_update` (`new==0`→Delete, `old==0`/absent→Push, else ff-probe→Push|ForcePush) so `allow_force_pushes` bites exactly when the real move isn't ff. Non-empty `reasons` ⇒ `Forbidden{verdicts: ProtectionBlockReasons}` — u1's wire-verbatim verdict shape. `force` toggles ff-ness handling ONLY — it never bypasses the check, never bypasses provenance: an UNLINKED old tip failing the git-side `is_ancestor` test ⇒ `RefConflict{actual: None}` even under `force` (git-only history is protected work, not a force-rewrite target). Exactly ONE hooked move — `fast_forward_ref` or `force_update_ref` carrying the real `actor_capability`; `update_ref`/`commit_files`/`push_to_url` are FORBIDDEN here. On CAS `Conflict`, `actual` re-reads as `Option<ChangesetId>` via the forward link — never a git oid.

## SR6.7 — Deterministic refusals, no degradation (BR6.23 — AC7.1.3)

`import_one`'s refusal inventory is total and typed `InvalidInput` — >64 parents, >65_535-byte message, unrepresentable timestamp, >512-char path, `.`/`..`/control-byte path, non-UTF8 path/message/ident, ident containing `<`/`>` after {control,0x7f}→'?' sanitize or empty post-sanitize, composed `Name <email>` > `MAX_AUTHOR_LEN` (255). Degradation (truncation, substitution, dropped parents) is never an option — a degraded import would fork convergence between lazy and explicit paths. `compose_author`/`manifest_diff` are PRIVATE in u4/u5 — the guards/diff are MIRRORED in-crate (no fingerprint-bound file edits); `validate_path` is `pub(crate)` and called directly.

## SR6.8 — Ident sidecars bound the raw-byte channel (BR6.12 — AC7.4.1)

`ident:{git_oid}`/`ident-cs:{cs}` rows store base64 raw author+committer bytes to close the byte-identical round-trip gap (changeset author fields are sanitized+length-capped; raw git idents are not). Bound: a commit whose serialized `IdentSidecar` payload exceeds `cursor_payload_max_bytes` refuses `InvalidInput` pre-create (the mysql `payload TEXT` ceiling is 65,535 bytes; the sidecar shares the column) — pathological >32KiB raw idents cannot wedge the derived index. Sidecar rows always carry `Some(cs)` covering so a `vcs_changesets` delete cascades them (FK `ON DELETE CASCADE` preserved by 0055's sqlite rebuild).

## SR6.9 — Fail-closed + no auth inside (BR4.16 precedent, BR6.20, NFR9)

`db.is_skipped()` ⇒ `DbNotConfigured` eagerly at `import_chain`/`lazy_import`/`export` ENTRY — a raw facade `String` failure must never pre-empt the typed variant. Zero authorization inside the module — u7 owns session/PAT/`vcs:admin` checks; `actor_capability` only ARRIVES here as a threaded value (the wire/session boundary resolves it — never defaulted to `"admin"` inside `GitInterop`; the extended `fast_forward_ref`/`force_update_ref` signatures make the capability an explicit parameter — the methods hardcode `"admin"` today at cli.rs:3275/:3433, so the four production call sites GAIN the literal `"admin"` argument, matching the current hardcode — behavioral no-op). Non-verdict checker failures map `Err(_) ⇒ Internal` opaque (logged, never echoed — devsecops-12); a u7 impl folding `enforce_push_quota`/`refs/pull/*` denies can only express them through the `reasons` channel verbatim — no typed quota variant crosses the trait.

## SR6.10 — Residual-risk register (owned here)

- **`active` marker is best-effort** — concurrent imports interleave subprocess work; convergence (insert-if-absent + idempotent create) is the correctness backstop, but the marker cannot prevent duplicated `rev_list`/`cat-file` cost on a raced import. Accepted — no CAS facade exists under the no-new-facade constraint.
- **Minted objects are unreferenced until the move** — a denied verdict or CAS conflict leaves the written chain as unreferenced objects reaped by `git gc --prune`; same exposure `commit_files` already carries. A re-export re-mints deterministically (content-addressed) — heals, never corrupts.
- **Best-effort mutex + crash mid-import** — a killed importer leaves `{active}` until TTL (900s) or nonce-mismatch reclaim; the durable cursor makes resume idempotent — `skip`/`last_oid` continuity rejects a misaligned resume rather than re-importing.
- **`rev_list` single-cone bound** — a >250k-ancestor cone trips `TooLarge` honestly; `rev-list` cannot express `^oid` exclusions so multi-cone repos import per-ref via `from`. Accepted tripwire.
- **`export_chain_max` deep histories** — >10k unanchored changesets trip `TooLarge`; the staged-export escape (export an intermediate head first, it becomes the anchor, re-export) is documented in WF4 — honest bound, never silent truncation.
- **Ident-sidecar payload share** — sidecars share the derived-index `payload` column; the 32_768-byte pin (SR6.8) makes overflow a typed refusal, not a silent db truncation.
- **`lazy_import` tip shadowing** — a branch literally named a 40-hex oid would shadow the target under head-preferred `from` resolution; the lazy path seeds `tips=[oid]` directly, bypassing `from` resolution (review3-F7). Named so the pin survives into codegen.
- **Alias twins share the forward link** — two distinct changesets minting the same git oid keep the FIRST minter's forward link (BR6.26) — an export of the twin resolves `RefConflict.actual` to the first minter's cs id, which is still provenance-correct (both are ours).
- **`ProtectionBlockReasons` surfaces verbatim** — verdict details (missing contexts, unsigned commits, review counts) reach the caller exactly as a push denial would — same information exposure the existing endpoint already emits; no new leak surface.
- **Concurrent git pushes during export** — a push landing between the ff-gate read and the ref move is caught by the backend's CAS (`fast_forward_ref` verifies `old`) → typed `Conflict` ⇒ `RefConflict` re-read; never a silent overwrite.
- **Each hooked ref move full-clones the bare repo** — `fast_forward_ref`/`force_update_ref` run `git clone` + `checkout --detach` to a tempdir per call (cli.rs:3423-3431/:3267-3273 — INHERITED backend cost, unchanged by u6): O(repo-size) disk/IO per export attempt, user-triggerable through u7's wire surface but behind the same protection/actor gates as any push. Accepted inherited cost — bounding it is a backend concern outside this unit's surface (devsecops-M3).
- **No timeout on the `run_git*` helpers consumed here** — the interop helpers wait indefinitely on a hung child (`ARCHIVE_TIMEOUT` wraps only `git archive`, not on this surface) (inherited backend behavior, devsecops-M3); a wedged git child blocks one spawned task without corrupting state (claim TTL + durable cursor make the import resumable). Accepted — a per-invocation timeout knob is a recorded v2 option, not silently added to shared methods that mirror/sync callers also use.
- **Stdout bound is derived, not exact** — the `tree_flat`/`commit_name_status` `max_bytes` args over-approximate real output (import_tree_max × 1-2KiB/entry); a hostile-but-legal tree with max-length paths could trip `TooLarge` below the leaf cap — honest typed refusal, never truncation (devsecops-M2 trade-off accepted).

## SR6.11 — Observability on typed-error and traversal paths (NFR8)

`tracing` spans on every public op with `unit=vcs.git_interop`; `warn!` on gitlink skips and non-commit tip drops (both counted — `skipped_tips` surfaces the count on the wire via the recorded DTO amendment); `info!` on claim/release, page windows, export outcomes. Logs carry repo_id, op, counts, oid/cs ids only — never blob contents, ident payload, stderr text, or auth material. `InteropError::Display` renders variant+fixed-detail — a listing impl that could smuggle stderr into logs is forbidden by construction (no raw-stderr field exists on the enum).
