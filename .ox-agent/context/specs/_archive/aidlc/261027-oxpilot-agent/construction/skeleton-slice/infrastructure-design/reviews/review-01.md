### Summary

The "zero new infrastructure" and "no ruleset change" claims are airtight against the repo — verified job-by-job in `ci.yml`, the Railway IaC, the versioning registry, and the coverage manifests. The monitoring doc stays inside NFR6 (tracing-only signals, no alert pipeline, smoke ceilings in a stack test) and the rollback/flag-off story is coherent. The blocker is R-01: the same-change registration set — this stage's core deliverable — omits the `run-stack-e2e.sh` harness env exports that U1's own enabled-path stack probe requires, and asserts a mechanism ("test-local env (or defaults)") that cannot work for a server-side flag that defaults off. Seven minors follow: two registration-set gaps (second route-coverage row + likely browser row; the `oxidean-api.depends_on` reverse edge), two attribution errors (coverage-weighted row conflating three jobs; NFR4.3's target pointing at a doc without the content), two precision defects (compression-exclusion locus; jobs-vs-make-targets naming), and one unverified durability claim (dashboard-set flag vs `railway config apply`). All are one-paragraph fixes; R-01 must land before code generation consumes the registration set.
