### Notes

- All twelve iteration-1 findings verified resolved in code; `cargo check` on the four touched crates is clean and `cargo test -p oxidean-api --test oxpilot` passes 10/10.
- Sanity checks requested: (a) claim-lost correctly distinguishes resend-vs-new — resend of an old cmid under a foreign live turn answers a snapshot (prior.seq mismatch + pending mismatch → `single_frame_stream`), a genuinely new message gets 409; (b) no-cmid resends in the pending window match on `started_seq == 0 && pending_content == content` (routes.rs:493-494); (c) `started_seq` is `AtomicI64` with SeqCst load/store everywhere — no torn access, single writer (claim holder); (d) both replay loops terminate on a buffered terminal frame (l.454-457, 509-513) and buffered terminals are always pushed before `release`, so the terminal-to-release window is safe.
- Non-blocking observations, deliberately not filed: routes.rs:9-11 doc comment omits `oxpilot.internal` from the vocabulary list (contract file is correct); `ChatRequest.messages` carries only the triggering user message — transcript-tail context is U3 scope; a secret spanning delta chunk boundaries can still reassemble client-side (code comment acknowledges the boundary); a `run_turn` panic would wedge the session map entry for the process lifetime (persisted orphans are swept at boot — main.rs:131); `emitted_deltas` is unbounded per turn.
- Coverage gap unchanged from iteration 1: still no test for mid-turn GET attach replay, resend-in-the-claim-window, or a Lagged resync — the races verified here are exercised by inspection, not by the suite.
