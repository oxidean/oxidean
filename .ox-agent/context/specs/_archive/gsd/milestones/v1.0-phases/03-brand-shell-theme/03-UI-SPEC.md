## Visual hierarchy & layout contracts

### Global header (D-03, D-10, D-11, D-18, D-19)

**Order (LTR):** `[Mark ± wordmark]` → flex spacer → `[Search Input]` → `[Theme Select]` → `[Sign in]` → `[Sign up]`

| Element | Contract |
|---------|----------|
| Mark | Shared `OxideanMark` component; macOS **squircle** clip of `brand/oxidean-mark.png` (via `public/`); **no** padded plate; same treatment light/dark; `alt="Oxidean"`; header size **32×32** |
| Wordmark | Text “Oxidean” in display font; **visible ≥ `sm`**; **hidden on narrow** (mark-only) |
| Search | ShadCN/Base UI **Input**, disabled, placeholder below; height ≥ 44px |
| Theme | ShadCN/Base UI **Select** (not native `<select>`); after search, before Sign in |
| Auth | ShadCN **Button** group: Sign in = `ghost` disabled; Sign up = `secondary` disabled; `title="Coming soon"` |

**Theme Select interaction (D-07, D-11):**
- Preference model: `system` \| `light` \| `dark`; persist `localStorage` key `oxidean-theme` (existing `theme.ts`)
- Closed trigger: **icon + short label** for current choice (`System` / `Light` / `Dark`)
- Menu items: **icon + text** for all three
- Icons (default from CONTEXT discretion): `Monitor` = System, `Sun` = Light, `Moon` = Dark (lucide)
- Height ≥ 44px; label/trigger text uses Label role (14px / 400)

**FOUC (D-12):** Inline boot script in document head **before paint** reads `oxidean-theme`, resolves system via `prefers-color-scheme`, toggles `html.dark`. React hydrate must not flash the opposite theme.

### Footer (D-06)

- Text-only: `© Oxidean` + link **Status** → `/status`
- **No** footer mark

### `/` Landing — section map (D-22…D-25)

**Layout language:** editorial bands / split rows — **no card grid**, no card clutter in hero or marketing bands.

| # | Band | Job | Focal / content |
|---|------|-----|-----------------|
| 1 | **Hero** (first viewport) | Brand-first composition | Large squircle mark (**96×96** default; discretionary ±16 within scale) + **one** Display headline + one Body support + CTA group. **No** duplicate “Oxidean” wordmark/text in hero (mark carries brand). Full-bleed cool↔warm radial atmosphere on bg (not flat). No stats, schedules, chips, overlays, or inset media cards. |
| 2 | **Dual-mode** (`id="explore"` target) | Cloud + self-host | Split editorial row: left “Oxidean Cloud”, right “Self-host” — one headline each + short body; **not** a card grid |
| 3 | **Collaboration pillars** | Why nest here | Horizontal or stacked editorial pillars (3 max): host git / collaborate / ship — typography + spacing, not bordered cards |
| 4 | **Closing CTA** | Reaffirm action | Short Display/Heading line + CTA group mirroring hero rules |

**CTA rules (D-24):**
- **Get started** — primary Button, **disabled** placeholder until Auth phase (`title="Coming soon"`)
- **Explore** — secondary Button/link; **scrolls** to `#explore` (dual-mode band); enabled

### `/status` (D-26, D-27)

- Marketed system-status page with **clear status hero** (not a small muted badge)
- Data: live `system.health` **only** (no history)
- Below hero: version + database detail in Label/muted text
- Status panel may use surface (`card`/`surface`) for readability — this is an interactive status container, not a marketing card grid

| State | Hero treatment |
|-------|----------------|
| Loading | Muted body: “Checking Oxidean services…” — no accent fill |
| Healthy | Cool **primary** accent on hero line “All systems operational” |
| Unhealthy / degraded | **Destructive** on “Degraded or failing” |
| Unreachable | **Destructive** on “Can’t reach the API” + recovery body |

## Spacing Scale

Declared values (multiples of 4 only):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline tight padding |
| sm | 8px | Compact control padding, mark↔wordmark gap |
| md | 16px | Default element spacing, header horizontal padding unit |
| lg | 24px | Section inner padding, CTA group gap rhythm |
| xl | 32px | Layout gaps, header height rhythm companion |
| 2xl | 48px | Major section vertical breaks between landing bands |
| 3xl | 64px | Page-level padding (status / landing vertical) |

**Exceptions:**
- Touch targets (Search, Theme Select, Buttons, CTAs): **≥ 44px** height (a11y; not on 8-pt scale)
- Header bar height: **64px** (`3xl` / `h-16`) — locked from existing chrome
- Content max width: **72rem** (`max-w-6xl`) for chrome + landing; status may use **48rem** (`max-w-3xl`) for readable hero column

**Source:** Phase 1 UI-SPEC + existing chrome; confirmed as default for Phase 3.

## Typography

Exactly **4** sizes and **2** weights project-wide for this phase:

| Role | Size | Weight | Line Height | Font |
|------|------|--------|-------------|------|
| Label | 14px | 400 | 1.4 | Source Sans 3 |
| Body | 16px | 400 | 1.5 | Source Sans 3 |
| Heading | 24px | 600 | 1.2 | Sora |
| Display | 40px | 600 | 1.15 | Sora |

**Weights used:** **400** and **600** only — no 500/700 in Phase 3 UI.

**Application map:**
- Header wordmark → Heading (24 / 600) on wide; mark-only on narrow
- Landing hero headline → Display
- Landing support / dual-mode / pillars body → Body
- Band section titles → Heading
- Status page title → Heading
- Status hero line → Heading or Display (prefer **Heading 24** if viewport feels dense; **Display 40** allowed for healthy/degraded hero — pick one consistently; default **Display** for status hero)
- Meta (version · database), placeholders, footer → Label
- Buttons / Select trigger text → Label size **14px**; weight **600** on primary/secondary CTA labels, **400** on ghost/muted chrome (both weights are in the declared pair)

**Source:** Phase 1 UI-SPEC + existing `styles.css` / chrome sizes; locked fonts from CONTEXT.

## Color

### Semantic token mapping (D-13…D-15)

Migrate off legacy `--color-accent-cool` / `--color-accent-warm`. Map Oxidean brand into full ShadCN semantic layer:

| Semantic token | Brand meaning | Notes |
|----------------|---------------|-------|
| `--primary` | **Cool / left** (blues–cyans) | Must read as logo cool side |
| `--secondary` | **Warm / right** (oranges) | Must read as logo warm side |
| `--background` | Dominant page bg | |
| `--card` / surface | Secondary chrome panels | Header, status panel |
| `--muted` / `--muted-foreground` | Supporting copy | |
| `--border` / `--input` / `--ring` | Chrome + focus | Ring uses cool/primary family |
| `--destructive` | Errors / degraded / unreachable | Not for warm brand accent |
| `--foreground` | Primary text | |

**Remove** all call sites of `--color-accent-cool` / `--color-accent-warm` in this phase.

### Light theme values

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F4F6F8` | `--background` — page canvas |
| Secondary (30%) | `#FFFFFF` | `--card` / header/footer / status surface |
| Primary / accent cool (≤10% with warm) | `#1B6FE8` | `--primary` — see reserved list |
| Secondary warm | `#F07818` | `--secondary` — see reserved list |
| Text primary | `#12141A` | `--foreground` |
| Text muted | `#5C6570` | `--muted-foreground` |
| Destructive | `#D92D20` | Degraded/unreachable hero + future destructive only |
| Border | `#D8DEE6` | `--border` |

### Dark theme values

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0B0C0E` | Mark-friendly near-black bg |
| Secondary (30%) | `#16181D` | Header/footer / status surface |
| Primary / accent cool | `#3B8CFF` | Lifted for contrast on dark |
| Secondary warm | `#FF8A2B` | Lifted warm |
| Text primary | `#F2F4F7` | |
| Text muted | `#9AA3B2` | |
| Destructive | `#F97066` | |
| Border | `#2A2F3A` | |

**Hex source:** existing `styles.css` (tuned tokens that already match logo cool/warm split). Executor may micro-tune toward mark samples but must keep primary=cool-left, secondary=warm-right and avoid purple-on-white / generic indigo slop.

### 60 / 30 / 10

- **60%** dominant background
- **30%** secondary surfaces (header, footer, status panel)
- **10%** combined primary cool + secondary warm accents

### Accent reserved for (explicit — never “all interactive”)

**Primary (cool) reserved for:**
1. Primary CTA fill (**Get started**) when enabled in later phases; disabled state still uses primary token at reduced opacity
2. Focus rings (`--ring`) on interactive controls
3. Healthy status hero line on `/status`
4. Theme Select selected-item indicator / check affordance (subtle)
5. Dual-mode band cool-side accent rule or underline (Cloud column only)

**Secondary (warm) reserved for:**
1. Secondary CTA outline / text accent (**Explore**)
2. Dual-mode band warm-side accent (Self-host column only)
3. Closing CTA secondary treatment paired with primary
4. Brand atmosphere gradients (radial cool/warm mesh — atmospheric only, not UI chrome fill)

**Destructive reserved for:**
1. Status degraded / unreachable hero lines
2. Future destructive actions (none confirmed this phase)

**Not accent:** footer links, disabled search chrome, disabled auth ghost/secondary beyond their defined variants, body links (use foreground + underline).

## Motion (D-25)

Ship **exactly 3** intentional motions (CSS keyframes preferred; Motion library optional):

| # | Motion | Spec |
|---|--------|------|
| 1 | Hero entrance | Mark → headline → support/CTAs stagger fade+translateY(8px→0), 200–400ms ease-out, ≤3 steps |
| 2 | Section reveal | Dual-mode / pillars enter on scroll (IntersectionObserver or CSS) — opacity + 12px rise, once |
| 3 | CTA hover | Primary/secondary Buttons: brightness or border-color micro-transition ≤150ms (no glow pulse loops) |

**Reduced motion:** all three disabled or instant under `prefers-reduced-motion: reduce`.

**Status:** soft opacity when health resolves (counts as part of reveal polish; do not add decorative loops).
