## Visual hierarchy & layout contracts

### Shared auth shell (`/verify`, `/reset-password`)

**Inherit Phase 4 auth shell exactly:**

| Rule | Contract |
|------|----------|
| Chrome | Global `SiteHeader` + `SiteFooter` |
| Page column | Centered; **max-w-md** (`28rem`); page padding **3xl** vertical / **md** horizontal |
| Brand | `OxideanMark` **48×48** above title — no duplicate wordmark in panel |
| Title | Heading (24 / 600 / 1.2 Sora) |
| Support | One Body muted sentence under title |
| Surface | Flat on `--background`; optional single `bg-card` panel only if needed for contrast |
| Atmosphere | Soft cool↔warm radial mesh allowed (same as login/signup) |
| Loading | Primary submit shows disabled + **Working…**; do not blank the page |
| Errors | `AuthErrorBanner` (`text-destructive`, Label/Body) above fields — problem + next step |

Reuse `AuthShell` + `AuthErrorBanner` components; do not fork a second shell.

### `/verify` (D-16, D-17, D-20, D-21)

| Element | Contract |
|---------|----------|
| Route | `/verify` — accepts `?token=` (magic link) and/or shows code form |
| Title | **Verify your email** |
| Support (default) | We sent a link and an 8-digit code to your email. Enter the code below, or open the link from the same device after signing in. |
| Token query flow | On mount with `token`: if **signed in** as target user → auto-consume (show **Working…** / “Verifying…” Body); if **anonymous** → Body “Sign in to finish verifying this email,” primary **Sign in** → `/login?returnTo=/verify?token=…` (preserve token in safe returnTo); if wrong user → error below |
| Code form | Label **Verification code**; `InputOtp` **8 slots**, numeric only, `inputMode="numeric"`, `autoComplete="one-time-code"` |
| OTP submit | **Auto-submit** when all 8 digits filled; also keep primary Button **Verify email** (≥44px, full-width on narrow) for a11y / paste edge cases |
| Resend | Ghost/secondary text Button **Resend email** under form; disabled while cooldown (show Label “You can resend in {n}s” or “Resend available shortly”) |
| Success | Redirect `/dashboard` or safe `returnTo` (same Phase 4 D-15 rules) |
| Already verified | Muted Body “Your email is already verified.” + primary **Go to dashboard** |
| Cross-link | Label-size: Need a different account? **Sign in** |

**Do not** display the raw magic-link token string in the UI (query may briefly appear in address bar; never echo into a read-only field).

### `/reset-password` (D-24…D-28)

Two visual states on one route (no separate `/forgot-password` path — forgot entry points here).

#### A — Request (no redeem token/code yet; default)

| Element | Contract |
|---------|----------|
| Title | **Reset your password** |
| Support | Enter your account email. If it matches a local-password account, we’ll send a link and an 8-digit code. |
| Field | Email `Input` `type="email"` `autocomplete="email"` |
| Primary CTA | **Send reset email** |
| Anti-enumeration success | Always show the **same** success panel (never “email not found”) — see Copywriting |
| Mode gate | Show request UI only when `provider_config.mode === local`. For `workos`/`oidc`: title still Reset; Body “Password reset is managed by your identity provider.” + CTA **Continue with WorkOS/SSO** (reuse Phase 4 labels) — no email form |
| Cross-link | Remembered it? **Sign in** |

#### B — Redeem (token query present and/or user choosing code entry)

| Element | Contract |
|---------|----------|
| Title | **Choose a new password** |
| Support | Enter the 8-digit code from your email (or continue from your reset link), then set a new password. |
| Code | Same `InputOtp` 8-digit contract as verify |
| Password | `Input` `type="password"` `autocomplete="new-password"`; helper: “At least 8 characters.” |
| Confirm | `Input` `type="password"` `autocomplete="new-password"`; client mismatch before submit |
| Primary CTA | **Update password** |
| Strength | Match Phase 4 signup: **minimum 8 characters**; no meter UI |
| Success | Set password → revoke other sessions → **signed in on this device** → redirect `/dashboard` (or safe `returnTo`) |
| SSO-only edge | If redeem fails with stable “SSO / no local password” class error: “This account signs in with SSO. Reset your password with your identity provider.” |

Magic-link redeem: auto-attempt when `?token=` present (same signed-out redeem path — reset is logged-out per D-27). Token not echoed.

### `/login` extension (local only)

| Element | Contract |
|---------|----------|
| Forgot entry | After password field (before Remember me **or** between Remember me and submit — prefer **after password field, before Remember me**): Label-size link **Forgot password?** → `/reset-password` |
| Modes | Link **only** when mode is `local`; omit for WorkOS/OIDC panels |
| Cross-links | Keep Phase 4 Login ↔ Signup; forgot does not replace them |

### Persistent verify banner (D-11, D-13)

| Rule | Contract |
|------|----------|
| Placement | Full-width strip **immediately under** `SiteHeader`, above `<main>` content — mount from root/chrome so it appears on all signed-in pages while unverified |
| Visibility | Signed-in **and** `auth.me.email_verified === false` only; hide when verified or anonymous |
| Surface | `border-b border-border` + `bg-card` (or subtle `bg-muted`); horizontal padding **md**; vertical padding **sm–md**; content max aligned with header rhythm |
| Hierarchy | Body/Label message first; actions second (no competing Heading) |
| Actions | Text/ghost **Resend email**; text link **Enter code** → `/verify` |
| Pending | Resend shows **Working…** / disabled; respect soft rate limit (~1/min, ~5/hour) with muted helper |
| a11y | `role="status"` (or `role="alert"` only if resend/verify just failed); do not steal focus on every navigation |
| Stacking | If profile-incomplete dashboard banner also shows, verify chrome banner stays global; page-local banners remain in page column |

### Privileged CTA pattern (D-12)

Until Phase 7 ships real create-repo:

| Element | Contract |
|---------|----------|
| Placement | `/dashboard` link row — add **New repository** primary Button |
| Unverified | **Visible**, `disabled`, `aria-disabled="true"`, `title` + visually associated Label/hint: “Verify your email to create a repository.” |
| Verified | Still disabled in Phase 5 with muted helper “Repository creation arrives in a later phase.” (gate proven; product create deferred) — **or** if executor prefers: verified users see enabled-looking secondary that still no-ops with same later-phase helper. **Lock:** unverified → disabled + verify hint; verified → disabled + later-phase hint (no fake create). |
| Accent | Disabled primary uses primary token at reduced opacity (Phase 3 disabled primary rule) — **not** warm secondary |

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | OTP slot gaps (tight), icon gaps |
| sm | 8px | Field↔helper gap; banner vertical padding unit |
